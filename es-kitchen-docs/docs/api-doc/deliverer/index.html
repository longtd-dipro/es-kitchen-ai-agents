配送関連 — Deliverer / Shipment

Bộ mockup + tài liệu API cho 2 phân hệ: Portal Deliverer (委託配送先 tự phục vụ — prefix /deliverer) và Admin (System Admin quản lý 配送スタッフマスタ + 出荷配送 — prefix /admin). Trang này là điểm vào: bấm màn hình để xem mockup, bấm API ガイド để xem interactive guide (click số → ráp field ↔ API), hoặc đọc tài liệu thiết kế (.md) để biết DTO/validation/quyết định DB.

1 · Phạm vi & quyết định kiến trúc đã chốt

Portal Deliverer/deliverer · DelivererGuard
＋
Admin/admin · AdminGuard + RBAC
→
お知らせ / 配送状況集金額 / 配送スタッフ / 出荷配送
🛡️
Scope guard (BẮT BUỘC): Portal Deliverer ép deliverer_id = me.id trên mọi query; mọi :id phải thuộc về mình, không thì 404. Admin không giới hạn scope nhưng qua RBAC permission keys (shipment.*, driver.*).
Quyết địnhNội dung
D1 · Gộp bảngdeliverers (login) và deliverer_masters (nghiệp vụ) là MỘT bảng → bỏ deliverer_masters; mọi deliverer_id trỏ deliverers.id.
D2 · NotificationTargeting polymorphic: recipient_type + recipient_id trên user_notifications.
LoginDeliverer/Driver đăng nhập bằng CODE (driverCode/delivererCode, sinh seq). Trong form: ユーザID=code (read-only khi xem), メールアドレス=email liên hệ (≠ login).
Quản lý 配送スタッフCả Admin lẫn Portal Deliverer đều quản lý driver.

2 · Convention API (BẮT BUỘC)

⚠️
Prefix route: Portal → /deliverer/... (DelivererGuard)  ·  Admin → /admin/... (AdminGuard + RBAC). DTO camelCase + class-validator; enum đặt tại src/commons/enums.

Response envelope

// wrap qua ApiUnifiedResponse
{ "statusCode":"success",
  "message":"...",
  "data": <payload> }

List / pagination

// Query (BaseSearchRequest):
?page=1&limit=10&q=&order=DESC&orderBy=createdAt
// MẶC ĐỊNH: order=DESC · orderBy=createdAt
// data:
{ "items":[...], "total":100,
  "page":1, "limit":10, "totalPages":10 }
