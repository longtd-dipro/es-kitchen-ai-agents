### 0.2 親契約と子契約の分担（2026/09/15 決定）

| | 持つもの |
|---|---|
| **親契約**（拠点画面のタブ） | 契約を通して変わらないもの：親契約番号・契約種別・契約状態・契約開始日／終了日・最低利用期間・最低利用期間の満了日・代理店コード（旧：他社乗り換えキャンペーン該当。値引きマスタの他社乗り換え割引に移したため削除） |
| **子契約**（契約情報編集） | 毎月決まる／途中で変わるものすべて：**プラン・コース・配送設定・納品スケジュール・料金（費目）・設備・請求ステータス・変更履歴** |

- **子契約は「1納品サイクルにつき1件」です。** 詳しくは §0.3 を参照してください。
- **翌月分の契約変更は、親契約ではなく翌月の子契約を直して行います。** 当月の子契約は確定・請求済になると金額に効く変更ができません。
- **「変更の適用月」という項目は持ちません。** 代わりに、子契約の**保存ボタンを押したときにダイアログで適用範囲を聞きます**。
  - **この子契約だけ** … この子契約のレコードだけ直す。翌月以降は元の設定のまま生成される
  - **この子契約以降すべて** … この子契約を直したうえで、生成元の設定（拠点・親契約・プラン）も同じ値に更新する。**自動生成は生成基準日（§0.3：請求書発行リードタイムで決まる。当月請求はオーダー開始日、2ヶ月前請求は2ヶ月前、年払いは12サイクル分）を過ぎたサイクルの分を作るので、生成元を更新しないと、そのあと生成される子契約が元の値に戻ってしまいます。**（旧：自動生成は1ヶ月先まで。2026-10-03 契約_01 §1 に合わせて修正） 手動で先の月まで作ってある未確定の子契約は同時に直し、**確定・請求済の子契約は直しません**
  - 選んだ結果は変更履歴の**「適用範囲」**に「2026-07 のみ」「2026-07 以降すべて」の形で残します。
- **配送が途中で変わる場合も子契約で変更**し、適用は翌月の子契約からになります。
- **料金は子契約が持ちます。** 請求ステータス（生成済〜請求済）を子契約で管理するためです。
- **変更履歴は、拠点・親契約と子契約の両方に持ちます。**
- 承認待ちの申請がある間は、その拠点の子契約で申請の対象項目を直接編集できない。承認するとき、申請の『変更前の値』と今の値が違えば承認を止め、運営に確認させる（契約_01 §1。2026-10-03 追加）。

### 0.3 子契約は「1納品サイクルにつき1件」。生成は暦の1日ではなく基準日で拾う（2026/09/15 改定）

納品サイクルは4週で回り、**サイクル初日（A1）は必ず月曜**です。暦の1日とは一致せず、**前月末日になることもあります**。そのため「毎月1日に1件作る」ではなく、次のようにします。

- **1サイクル＝1子契約。** サイクルが暦月をまたいでも分けません。**サイクル月＝14番目の枠（B7）が属する月**（決定_v2.1・2026/09/21）で、子契約番号の `yyyymm` はサイクル月を指します（請求月は別項目）。
- **判定の使い分け**：プラン固定額とオーダーの月次提供数上限は**サイクル月**で判定し、分納・再配達・スポットは**納品日の暦月**で判定します。
- **生成は日次バッチ**が「**基準日を過ぎた未生成のサイクル**」を拾います。暦日固定ではありません。
- **生成基準日は請求書発行リードタイムで決まります。**

| 支払パターン | 子契約の生成タイミング | 例（2026年9月サイクル） |
|---|---|---|
| 当月請求（標準） | サイクルのオーダー開始日 | 2026-08-01 に生成 → 2026年9月請求 |
| 2ヶ月前請求 | サイクル月の**2ヶ月前**までに生成 | 2026-06-25 までに生成 → 2026年7月請求 |
| 1年一括前払い | 契約開始月・更新月に**12サイクル分をまとめて**生成 | 2026-04 に 2026年4月〜2027年3月の12件 |

- **契約種別で自動生成の有無が変わります。** **本導入**は自動更新で、基準日を過ぎた1サイクル分を自動生成。**お試しキャンペーン**は自動生成せず、指定した月数だけ作ります。どちらも先のサイクルが要るときは、拠点の「契約」タブ・一覧（子契約）の上にある**「子契約を先まで作る」**を押し、ダイアログで月を選んで、作られる子契約を確かめてから作ります（すでにあるサイクルは作り直しません）。
- **請求漏れ検知**：請求確定日（毎月25日）に、**有効な契約なのにその請求月の子契約が無いもの**を検出して「要確認」に出します。子契約が無いと請求ステータスを追えないためです。
- **解約・休止を承認すると、適用月以降の未請求（未確定）の先行子契約を取り消します。** 取消件数を承認画面に出します。契約終了月は「納品の最後の月」です。

> **解決（2026/09/21 決定_v2.1）**：サイクル月は「A1が属する年月」ではなく**「B7が属する月」**です。例の「2026年9月サイクル（A1＝2026-08-31）」は B7＝2026-09-13 なので9月サイクルで正しい。

### 0.4 お試しキャンペーンと本導入は同じ親契約で切り替える（2026/09/16。2026-10-03 台帳に合わせて修正）

|  | お試しキャンペーン | 本導入 |
|---|---|---|
| 料金 | お試しキャンペーン割引（DC000013）：値引き額＝プラン50・冷蔵庫・ライトのプラン料金（¥24,500）。請求額を超えない・1法人1回（**請求先が拠点ごとのときは最初の拠点に付ける**）。1拠点・50ライトなら無料。複数拠点・プラン変更・期間延長では差額を請求（2026/10/01 STEP1 回答）（旧：請求先が拠点別のときの付け先なし。2026-10-03 台帳に合わせて修正）<br>**お試しの延長分は割引しない（プラン料金を請求）**〔hong 回答 2026-10-03（K1）〕| 有料 |
| 期間 | 既定1ヶ月。顧客は編集できない。**延長は運営だけ**が行う（回数・月数の上限は当面なし。長くなるなら本導入へ）。法人Web にはお試し期間と延長分を表示（2026-10-03 課題一覧で追加） | 自動更新（前月更新） |
| オーダー | 法人はオーダーできない（2ヶ月以上でも同じ）。オーダーは毎月システムが自動で作る（いろいろな商品を均一に体験してもらうため）。資材ボックスは配る〔原典：契約_詳細要件 要件(2026/10/02) REQ-CT-302〕 | 法人がオーダー |
| 既定プラン | ライト。配送回数はプランに応じて自動調整 | 申込内容どおり |
| **最低利用期間** | **なし** | 設備ごと（機種マスタ。冷蔵庫3ヶ月・自販機12ヶ月）。貸出日から数える。お試し中に置いた設備は本導入の開始日から（2026/10/01 STEP2 回答 Q8・§0.6） |
| **違約金** | **発生しない** | 満了日より前の解約で発生 |
| 子契約 | 自動更新せず、お試し期間の月数ぶんだけ作る | 自動更新で1サイクルずつ生成 |

- **切り替えても親契約番号は変えません。** 親契約に**契約種別の履歴**（お試し：開始〜終了、本導入：開始〜）を持ち、最低利用期間・違約金・自動更新は**本導入の開始日から**判定します。拠点と親契約は1対1のままです。お試し満了から本導入開始まで間があくときは休止と同じ扱い（28-35）、通算1年を超えるときは切替ではなく新規申込（28-37）。お試し中に置いた設備がプランの標準貸出設備より多いときは、差額を本導入の最初の請求書で1回だけ請求し（運営が機種・金額を直せる）、少ないときは返金しない（課題一覧 10/02）。（旧：切り替えると新しい親契約番号を採番し、お試し側の親契約は終了のまま履歴として残す。2026-10-03 台帳に合わせて修正）
- 切替は親契約の「契約種別の履歴」に1行足すだけで、親契約どうしを指し合う項目は持ちません。ゲストモードなどの拠点設定は引き継ぎ、プラン・設備（例：CSC120→CSC180）は運営が切替時に設定し直せます。切替は拠点ごとに個別に行えます。（旧：親契約の「お試し・本導入の切替（参照）」でお互いを指す。2026-10-03 台帳に合わせて修正）
- お試しキャンペーンと本導入の**同時申込は想定しません**。

> <br>お試しと本導入の間が空くとき、親契約は「利用休止」〔hong 回答 2026-10-03（K2）〕
> お試し→本導入でプランが下がることはない（お試しはプラン50＝いちばん下）。設備の差額の計算は不要〔hong 回答 2026-10-03（K10）〕。

### 0.5 請求まわりは「どれが正か」を1つに決める（2026/09/15）

同じ名前の項目が法人と拠点の両方にあると、どちらが正か決まらず整合性が崩れます。次のルールで**持ち主を1つに固定**します。

| 項目 | 正となる持ち主 | 相手側の扱い |
|---|---|---|
| **請求先**（法人／この拠点） | **拠点のみ** | **法人には持たせない。** 法人画面には「請求先の内訳（参照）」として集計だけ出し、そこから拠点の請求先を一括変更する |
| 請求書の発行単位（まとめて／拠点ごと） | **法人のみ** | 拠点画面では参照表示のみ。**法人は参照のみ**、変更は運営（お問い合わせで受ける）（旧：法人から変更申請でき、運営承認が必須。2026-10-03 請求ルール 4-6 に合わせて修正） |
| 法人名 | **法人名／法人名（契約）／請求先法人名の3つ** | 画面表示は法人名、契約書は法人名（契約）、請求書の宛名は請求先法人名。空欄なら 請求先法人名 → 法人名（契約） → 法人名 の順にさかのぼって使う |
| 請求書発行リードタイム | **法人が既定値**、拠点が上書き | **選択式**：3ヶ月前（−3）／2ヶ月前（−2）／1ヶ月前（−1）／当月（0）／翌月（+1・後払い）。請求月 ＝ サイクル月 ＋ この値（2026/09/29 変更）。**上書きは請求先＝この拠点 のときだけ活性**（請求先＝法人なら法人の値に従い、非活性で保存もしない）。法人なし拠点は請求先が必ずこの拠点になるため必須入力 |
| 支払方法・支払サイクル（年払いのときは起算月）・入金期限（請求月の27日／翌月27日） | **請求先が指す側** | 請求先＝法人 → 法人の値を使い、拠点側は非活性で保存もしない。請求先＝この拠点 → 拠点の値を使い、法人側は使わない |
| Bill One 発行先ID | **請求先が指す側** | 同上 |
| 請求担当者・送付先メール | **請求先が指す側の担当者タブ** | 法人・拠点のどちらも担当者テーブルで持ち、区分が「請求担当者」の人が請求書の宛先になる。請求条件の欄には参照表示だけを置く |

> **子契約側は「そのとき有効だった値のスナップショット」です。** 子契約の請求先・請求書発行リードタイム・支払方法・支払サイクルは、生成時に固める。宛名・送付先（請求先法人名・請求担当者）は請求書の**発行時**に固める（契約_01 §2・Q5）。後からマスタを直しても過去月の請求条件は変わりません。（旧：支払方法・支払サイクルだけ写す。2026-10-03 契約_01 §2 に合わせて修正）

### 0.6 設備の貸出は拠点が持ち、回収は検知でしか守れない（2026/09/16）

設備を子契約に持たせると、毎月コピーされるだけで「**いつ貸して、いつ返ってきたか**」という月をまたぐ事実がどこにも残りません。そこで**設備の貸出は拠点の「設備・オプション」タブ**が持ち主とします。拠点に紐づくので、お試し→本導入の切替（同じ親契約）や休止・再開をはさんでも貸出は続きます（旧：お試し→本導入で親契約が変わっても、冷蔵庫は置きっぱなしなので。2026-10-03 台帳に合わせて修正）。

**登録するのは子契約、見るのは拠点です。** 持ち主（＝いま何を貸しているか）は拠点に1つだけ置き、**貸出・追加・回収・機種変更の登録は子契約の「設備の異動（この子契約で登録）」**で行います。異動は「いつの契約の話か」が必ずあり（プランアップに伴う入替、解約に伴う回収）、料金も同じ子契約の①に立つので、登録は子契約に置くのが自然です。**拠点の貸出一覧は見るだけ**にして、直せる場所を1つに絞ります。

| | 子契約「設備の異動」 | 拠点「設備・オプション」 |
|---|---|---|
| 役割 | **登録する**（新規貸出／追加貸出／回収／機種変更） | **見る**（いま何を貸しているかの一覧） |
| 行の単位 | 1回の異動 | 1つの貸出（LN-0001…） |
| 編集 | できる | できない（異動の結果が反映される） |
| 期間 | その子契約の月のできごと | 月をまたいで続く |

異動を登録すると、拠点の貸出一覧にこう効きます。

| 異動区分 | 拠点の貸出一覧での動き |
|---|---|
| 新規貸出 | 新しい貸出IDを採番して行を起こす |
| 追加貸出 | 既存の貸出の**貸出数**を増やす |
| 回収 | **返却済数**を増やす。未返却数が0になったら回収済 |
| 機種変更 | 旧の貸出を回収し、新しい機種で行を起こす |

**同じものを2か所で直せる状態は作りません。** 機種・台数・料金がどちらの画面でも直せると、どちらが正か分からなくなります。

| 何を | 持ち主 | 子契約での扱い |
|---|---|---|
| 何をどこに何台置いているか | **拠点の「設備・オプション」** | 「設備の構成（参照）」で要約とリンク。増減は「設備の異動」で登録 |
| 設備の初期料金・月額料金 | **子契約①の請求額の費目行**（出どころ区分＝model） | 金額を直すのは①の表。「設備の料金（参照）」で合計だけ |
| 機種の仕様・標準の料金・最低利用期間 | **機種マスタ** | 参照のみ |

**貸出数・返却済数・未返却数の3つを持ちます。** これなら個体管理でも員数管理でも同じ形で扱えます（2箱貸して1箱返却＝未返却1）。**個体番号は列だけ用意して、いまは空欄可**。把握できるようになったら埋め、将来は1個体1行に割る移行ができます。

| 状態 | |
|---|---|
| 配送中／貸出中／回収依頼中 | まだ返ってきていない |
| 回収済 | 未返却数が0。既定で非表示 |
| **未返却** | 返却予定日を過ぎても未返却数>0 |

**回収忘れの担保はアラートだけです。** 引揚費用がかからず、回収してもお金が動かないため、**催促する動機がどこにも生まれません**。請求は毎月立つので放っておいても誰かが気づきますが、回収は誰も困らないまま何年も過ぎます。

- 解約・休止を承認した時点で、貸出中の設備すべてに**返却予定日を自動で立てる**（既定は停止日＋1ヶ月。REQ-CT-144 の『1ヶ月』を設備の回収までの猶予と読み替える。個人アプリの購入は解約日まで。読み替えはお客様確認待ち）（旧：アプリ利用終了と揃える。2026-10-03 契約_01 §6-4 に合わせて修正）
- 日次バッチで「**返却予定日 < 今日 かつ 未返却数 > 0**」を**回収未完了**として運営の一覧に出す
- 未返却が続いた場合の請求・弁済金は**作りません**（運用がまだないため、検知までにとどめる）

**料金は機種マスタが持ちます。** 資材ボックスも BX で機種マスタに登録し、標準設備対象プランを 初期0・月額0 にします（将来有料化するときは数字を入れるだけ）。**0円の設備は請求書に出しませんが、契約には貸出中として残ります。** 子契約側に残るのは「条件つき無償」の理由を書く**無料判定**だけです。

**最低利用期間も機種マスタが持ちます**（冷蔵庫3ヶ月・自販機12ヶ月。2026/10/01 STEP2 回答 Q8 で確認し、機種マスタのデモも 3／12 に合わせた）。親契約の最低利用期間は**いちばん長い設備の代表値（参照）**で、**違約金は設備ごとに判定して合算**します。冷蔵庫は満了しているが自販機はまだ、という状態が普通に起きるためです。

**機種変更（プランアップ・ダウン）は「設備の異動」の異動区分の1つです。** プラン変更は月単位、設備の入替は物理的に1回なので、**どの子契約で登録したか**がそのまま適用月になります。子契約で登録する形にしたことで、プラン変更の変更申請と設備の入替が同じ月の画面に並び、「プランは9月から変わったのに設備は10月に入った」というズレに気づけます。

> **「冷蔵庫なし」は選べる**：申込フォームと設備の変更で、冷蔵庫等に「なし」を選べる（なしのときはタイプ・台数を入力しない）〔hong 回答 2026-10-03（K16）〕〔原典：REQ-CT-174・175〕。

### 0.10 法人Webに出さないもの（2026/09/15 定例で決定）

| 出さないもの | 理由 |
|---|---|
| **変更履歴**（法人・拠点・親契約・子契約のすべて） | 運営の担当者名が露見するため。変更があったときは運営から連絡し、運営Webの履歴で確認する |
| **子契約の「料金・請求」タブ全体** | 料金設定が見えると、法人に見せたくない項目まで見えてしまうため |
| **配送ルート設定**（ピッキング倉庫・配送会社・途中経由・リードタイム・問い合わせURL） | 内部の物流管理情報のため |
| **添付資料（社内のみ・非公開）** … 委託配送業者向けの搬入経路資料、運営側の追加資料 | 委託業者向け・社内運用の資料のため。法人に見せる資料は「添付資料（法人に公開）」に分けた |
| 代理店コード（紹介有無）／社内備考／ES営業担当／Bill One 発行先ID | 社内運用の情報のため |
| ユーザー現金利用 | 現金が使えると誤解させるため |

**出すもの**：納品回数・納品サイクル・配送回数は、法人から変更申請できるようにするため参照可能にします。
