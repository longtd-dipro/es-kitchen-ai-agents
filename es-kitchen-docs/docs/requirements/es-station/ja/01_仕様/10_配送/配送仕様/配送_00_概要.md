## 0. 本書について

### 0-1. 目的

配送・スケジュール（配送サイクル）・出荷・ピッキングの仕様は、**設計仕様**（`納品サイクル設定_仕様書.md`）と**議事録由来の要件**（`ピッキング出荷配送ドライバー_詳細要件仕様.md`）の2本に分かれていた。本書はそれらを**業務フローの順に1本へ通した**もので、「どの順に何が起きて、どこで何が決まるか」を先頭から読めるようにすることを目的とする。

### 0-3. 位置づけ（正・参照の関係）

**2026-10-03 から：配送の仕様の正は `配送仕様/` フォルダ（本書を章ごとに分けたもの）だけ。** データモデル（テーブル・列・制約）も `配送仕様/` に日本語で入れる。いま有効な決定は `docs/決定台帳.md`（仕様と食い違ったら台帳が正）。

### 0-5. 編集方針

1. **推測で埋めない。** 仮置きは **【暫定】** と書く。
2. **決定が最優先。** 2026/09/29 追補4 ＞ 2026/09/29 追補 ＞ 2026/09/24 追補 ＞ 第4次 ＞ 第3次 ＞ 第2次 ＞ 第1次 ＞ 原典。旧は「（旧：〜。2026/09/23 第4次で変更）」と括弧に残す。
3. **残っている食い違いは隠さない。** 57 件を本文に `⚠️ 要確認 #N` として置き、§20 に一覧を作った。
4. **用語を統一した。**「配送サイクル」／「出荷不可」／「一部納品」／「倉庫マスタ」／「納品不可曜日」／「前倒す・後ろ倒す」。**`plan lifecycle` と `delivery status` はまとめて「ステータス」と呼ばない。**

### 1-2. 一気通貫フロー

**`locked` の起点は1つだけ**〔決定v2.1 #3〕〔要件 REQ-DL-867・868〕〔サイクル §1.4〕

| 事象 | `plan lifecycle` への影響 |
|---|---|
| 出荷指示CSVを**出力（作成）**した | **遷移しない**（`published` のまま） |
| **出荷指示が初めて送信成功した** | **`locked` へ遷移する（唯一のトリガー）** |
| **送り状番号が付いた** | **遷移しない** |
| **出荷指示より先に送り状番号が現れた** | **`published` のまま ＋ anomaly（異常）として検知・通知**し、要確認に出す |

- ⑦の中では**トラブルの確認 → 複製 → ドライバー割当**と回ることがある（複製した子レコードには担当を割り当て直す）。**回るのは⑤以降だけ**で、②③へは戻らない〔サイクル §1.1〕
- **当月請求の子契約の生成日は「オーダー開始日」**（配送データの確定生成と同じ日）に揃える〔要件 REQ-DL-841〕〔決定 #40〕
- 節目（メニュー公開＝オーダー開始／オーダー締切）は配送サイクル側で算出せず、**メニュー側が正**。**サイクル生成時に実日付を写し取ってサイクルに保持**する。メニュー未登録のときは**前月15日を仮の締切**（`marker_source = provisional`）とし、**仮の締切のあいだにできるのは変更受付の締め切りと検査の起動だけ**で、**数量確定・確定メール送信・出荷指示は走らせない**〔決定v2.1 #9〕〔要件 REQ-DL-879・840〕
- **配送区分「資材」は④⑤の対象外。** 資材の配送データは**資材のカートを確定したたびに**作り（同じ拠点・同じ納品日・出荷指示前の資材便があれば1件にまとめる〔決定v2.3 #36〕）、納品予定（`draft`）の段階を持たない。**都度配送（`on_demand`）は資材のみ**〔サイクル §4A-2C〕〔決定 #24〕

**逆流させないためのルール**〔サイクル §1.5〕

1. **後の段階から前の段階のデータを書き換えない。** 個別の配送データを直したいときに**倉庫マスタ**や配送サイクルを触らない。逆に①②の設定変更が `published` 以降に当たった場合は自動で書き換えず「要確認」に出す
2. **日付を作るのは③④のバッチだけ。** それ以降は「ずらす」だけで、計算式を持たない
3. **記録は消さずに足す。** 取消・中止・複製のいずれでも元のレコードを残す（請求と監査のため）。**未処理も残さない**（要確認・確認中・複製直後はすべて運営スケジュールの「要確認」に載る）
4. **理由を必須にする。** 日付の手動変更・一括変更・承認済みオーバーライドの取消・倉庫変更・予定削除・取消・中止・複製は理由の入力を必須とする（**締切前の「1回だけの変更」だけは理由が任意**。履歴は必ず残す）

## 2. 用語と ID 体系

### 2-1. 用語定義

| 用語 | 定義 | 出典 |
|---|---|---|
| **配送サイクル** | 28日を1周とする全社共通のスケジュール。4週（A/B/C/D）× 7日 ＝ 28スロット（`A1`〜`D7`）。**週 × 曜日**で構成し、A1は必ず月曜、A6は必ず土曜。**呼称は「配送サイクル」に統一**（「納品サイクル」は使わない） | 〔サイクル §0・§0-0〕〔決定 #20〕 |
| **納品スロット（枠コード）** | サイクル内の1日を指す識別子 `A1`〜`D7`。**「週（A〜D）× 曜日（1=月…7=日）」と常に一致する**。**スロットが決めるのは納品日であり、ピッキング日ではない** | 〔サイクル §0〕 |
| **サイクル月** | そのサイクルの呼び名になる年月。**14番目の枠 `B7` が属する月**（§2-3） | 〔サイクル §4.2〕〔要件 REQ-DL-881〕〔決定v2.1 #11〕 |
| **納品日（着日）** | 法人に商品が届く日。**すべての日付計算の基準（アンカー）** | 〔サイクル §0〕 |
| **ピッキング日** | 倉庫が出庫作業を行う日。**常に「納品日 − リードタイム」で逆算**される。この向きは全モードで共通で、逆転しない | 〔サイクル §0〕 |
| **リードタイム** | ピッキングから納品までの日数。**契約の配送区分（冷蔵／冷凍／資材）ごと**に持ち、範囲は **0〜7日**。**倉庫マスタは持たず、既定値の自動補完もしない**。中継があっても**合計1つが正**で、1次・2次の内訳は参考表示にとどめる | 〔サイクル §12-1〕〔要件 REQ-DL-831・832〕〔決定 #10／#16／#52・#4・#21〕 |
| **サイクル休止（配送サイクル休止期間）** | 夏季休業・年末年始・長い連休など、サイクルの進行そのものを止める期間。休止日には**スロットを割り当てず、枠も消費しない**。止まった枠は**休止明けの翌日から順に再開**し、サイクル全体が休止日数ぶん後ろへずれる。**納品回数は減らない** | 〔サイクル §0・§2.2〕〔要件 REQ-DL-807〕 |
| **納品祝日扱い日** | 契約側の「祝日納品不可」ルールを適用する日。該当契約だけ納品日を振り替え、祝日納品可能な会社には通常どおり納品する。**全社一律の納品不可ではない** | 〔サイクル §0・§2.3〕 |
| **出荷不可** | その倉庫でピッキングできないこと。枠で指定するものを**出荷不可枠**、日付で指定するものを**出荷不可日**と呼ぶ（「ピッキング不可」「出荷NG」「P不可」は使わない） | 〔サイクル §0〕 |
| **出荷不可枠** | 倉庫が作業しない枠を「週 × 曜日」の軸（`A1`〜`D7`）で指定したもの。**同じ木曜でも週Aは稼働・週Bは休み**のように週ごとに変えられる。**倉庫ごとに1組**で、設定対象期間の全体に適用する | 〔サイクル §0・§2.3〕〔要件 REQ-DL-722・804〕 |
| **出荷不可日** | 定休日・棚卸し・設備点検などにより、その倉庫でピッキングできない日。**開始日〜終了日の期間で登録できる**。倉庫ごとに保持する。**当たった場合はピッキング日・納品日の両方を振替の対象にする** | 〔サイクル §0・§2.3〕〔要件 REQ-DL-842・689〕〔決定 #15〕 |
| **納品不可曜日** | 法人（拠点）側が受け取れない曜日・祝日。**契約（拠点）単位**で持ち、**納品日のみ**を制御する。物理名 `ng_weekdays` はそのまま（旧称「受取不可曜日」は使わない） | 〔サイクル §0-0・§3.1〕〔決定 #31〕 |

| **自動子（トラブルの自動子）** | **種別マスタで「作る」になっている種別（誤配送・不在・破損）のトラブル報告を登録したとき**に、システムが同じトランザクションで作る子の配送データ。`確認中`・`duplicate_type=trouble_pending`・`creation_source=trouble_auto`。日付・数量は仮で、運営（物流）が確定するまで出荷指示・送り状・割当・請求・通知・みなし完了の対象外。**トラブルが起きた配送1件につき、生きているものは最大1件**（旧：期限を過ぎたらバッチが作る・1報告に1件。2026/09/29 変更） | 〔決定v2.3 #23・#29・#30〕〔DEV §13.2.1〕 |
| **中継（relay）** | 倉庫と納品先の間に中継先（配送会社の営業所。委託配送会社の拠点も可〔決定v2.3 #50〕）が入ること。**持つのは「中継あり／なし」の2値だけ**で、**route legs から導出し、状態としては保存しない**。**2段以上の中継は想定しない**。ドライバー割当は**区間（レグ）単位**で、**運送会社の区間は割り当てず、自社・委託の区間は割り当てる**（旧：運用は当面 2次〈中継先→納品先〉だけ割り当てる。2026/09/29 置き換え〔決定v2.3 #48〕）。中継先での受取は区間ごとの受取時刻で残す〔決定v2.3 #49〕 | 〔サイクル §4C-2〕〔要件 REQ-DL-876・836〕〔決定 #60〕〔決定v2.1 #7〕〔決定v2.3 #48〕 |
| **便種別（`service_form`）** | **ES配送便／COOL配送便／資材便**。**配送区分（delivery channel）が持つ入力項目**で、**契約のルートには置かない**。中継の有無からは導出しない | 〔サイクル §4C〕〔要件 REQ-DL-875〕〔決定v2.1 #7〕 |

### 2-2. 枠コードの読み方

- 枠コードは **週（A／B／C／D）× 曜日（1=月・2=火・3=水・4=木・5=金・6=土・7=日）**。`A6` は週Aの土曜、`B5` は週Bの金曜と読む。画面では不可枠のボタンに曜日を併記する（`A6 土` など）〔サイクル §0・§2.3〕
- **`A1` は必ず月曜。** 初回A1（配送サイクル初日）は月曜固定で、月曜以外を入力した場合は**直前の月曜へ丸めて**生成し、丸めた結果を画面に表示する〔サイクル §2.3〕 サイクル休止があると枠は休止日数ぶん後ろへずれるが、**休止は必ず7日の倍数へ丸められる**ため、**枠と曜日の対応はずれない**（次のサイクルの `A1` も月曜のまま）〔サイクル §4.2〕〔要件 REQ-DL-819〕 **同じ曜日でも週ごとに稼働・休みを変えられる**のが週×曜日で持つ理由で、B週・D週に木・金まで出荷しないのは、その週の配送件数が少なく倉庫が隔週で休んでいるため〔サイクル §2.3〕
- **出荷不可**枠の既定値は **A6・A7／B4〜B7／C6・C7／D4〜D7**。ここから自動判定される**納品不可枠は A1・B1・C1・D1（毎週の月曜）**で、固定値ではなく**出荷不可**枠の変更に合わせて再計算する。サイクル境界は循環して判定する（D7の次はA1）。**日曜を固定の出荷不可・受取不可にしない**〔サイクル §2.3・§5.3〕〔要件 REQ-DL-818〕
- 枠がグレー（選べない）のときは、**セルには短く**「B1 月（納品不可）」と出し、**詳細はツールチップ**で**出荷不可**枠・倉庫名・リードタイムを出す〔要件 REQ-DL-847〕〔決定 #23〕

### 2-3. サイクル月 ＝ 14番目の枠 `B7` が属する月

| 観点 | 内容 |
|---|---|
| **定義** | **サイクル月（サイクル名）は、14番目の枠 `B7` が属する月**とする。**例外の分岐は作らない** |
| 「日数が多い月」との関係 | この規則は**「枠 A1〜D7 の28日のうち日数が多い月」と常に同じ結果**になる。28日のうち前半14日と後半14日の境目が `B7` と `C1` の間にあるため、日数が多いほうの月には必ず `B7` が入る |
| **14対14 のとき** | **そのまま `B7` の月＝前の月**になる（例：`A1`＝2027-01-18 なら 1/18〜31 が14日、2/1〜14 が14日で、`B7`＝1/31 なので **2027年1月サイクル**）。**同数のための場合分けは持たない** |
| 数える範囲 | **数えるのは枠の日付だけ。** サイクル休止日は枠を消費しないので数に入れない。休止で暦上の長さが伸びても `B7` の位置は枠の並びで決まるため、サイクル月は変わらない |
| 例 | `A1 ＝ 2026-09-07` のサイクルは 9/07〜10/11（9/21〜27 はサイクル休止で枠を使わない）。`B7` は 2026-09-20 なので **`2026年9月 サイクル`**（日数でも9月17日・10月11日で同じ結果）。2026/10/01 STEP4 Q1＝A で配送管理の暦に統一（旧の例：A1＝2026-08-31） |
| 子契約ID | `契約ID-yyyymm` の `yyyymm` も**同じ規則**で決める。**1サイクル＝1子契約**で、月をまたいでもサイクル月の子契約に載せる |
| 請求月との関係 | サイクル月と請求月は一致しないことがある。**請求月は `billing_month` に別途持つ** |
| ほかに効くところ | プラン固定額・オーダー（月次提供数上限）の判定、**契約の倉庫・配送ルート変更の適用月**（そのサイクルの A1 から切り替え）、そのサイクルの節目として使うメニュー（＝サイクル月のメニュー） |

〔サイクル §4.2・§4A-2〕〔要件 REQ-DL-839・864・881〕〔決定v2.1 #11〕
