## 2. 承認区分（項目ごと）

**承認区分は項目ごとに決める**（法人情報の変更・拠点情報の変更の両方）〔STEP1「承認区分」、台帳「法人情報の変更の承認」。影響範囲 B-5 の「未決」は解消〕。区分は次の4つ。

| 区分 | 法人Web で保存すると | 運営 | 出どころ |
|---|---|---|---|
| **承認必須** | 承認待ちの申請（`CH-`）になり、承認後に反映 | 承認・却下する | 28 §5、STEP1 |
| **通知のみ**（即反映＋運営へ通知） | すぐ反映 | お知らせで知る | STEP2 Q3・Q10 |
| 承認不要（すぐ反映・通知なし） | すぐ反映 | — | 契約_03〜05 の項目表 |
| **運営のみ** | 法人Web では参照だけ（変更・申請できない） | 運営が直す（お問い合わせで受ける） | 28-31、行157 |

## 3. 申請の共通ルール

### 3-1. 1申請の中身

| 決まり | 出どころ |
|---|---|
| **1申請1種類**（手続きを混ぜない）。例外は再開（§6-7） | 28-22、28-13 |
| **1申請に複数の拠点を入れられる**（同じ手続きなら）。開始したいサイクル月は拠点ごとに選べる | v2.3 ⑥、今の画面 |
| 申請者：共有アカウントなので、送信時にご担当者の表の「お申し込み者」をラジオで選ぶ（必須）。残すもの：アカウント・選んだご担当者・その時点の氏名 | 法人Web §1-2、契約_04 申請履歴 #4 |
| ご事情・ご要望：任意・複数行 500文字 | 課題一覧 10/03 |

### 3-2. 承認の単位と状態

| 決まり | 出どころ |
|---|---|
| **拠点ごとに承認・却下する**（法人情報の変更は法人1件として） | v2.3 #1・⑥、今の画面 |
| 申請の状態：承認待ち／**対応中（処理した数/全体。例「対応中 1/3」）**／承認済み／一部承認／却下／取り下げ済み（まだ承認待ちの拠点が残っている＝対応中・全拠点が承認済み＝承認済み・全部処理して承認と却下が混ざる＝一部承認・全部却下＝却下）（旧：対応中は「一部処理済み」）〔hong 回答 2026-10-05（#2）〕 | v2.3 ⑥、今の画面 |
| 拠点（申請明細）の状態：承認待ち／承認済み／却下／取り下げ済み | 契約_04 申請履歴 #7 |
| お客様への通知は**拠点ごと**（1拠点の承認を待って全部を止めない） | v2.3 ⑥ |
| **承認した申請は参照だけ。直したいときは新しい申請を出す**（承認の取り消し・やり直しはしない） | 課題一覧 10/02「4-8」 |

- 運営の申請詳細の「やり直す」はなくした（2026-10-03・受付簿 No.11）。承認・却下した拠点はその場で確定。
- 状態「一部処理済み」と「一部承認」の違いが分かりにくい〔受付・承認画面_項目ギャップ「ステータスの整理」〕。⚠️ 名前の整理（§13 B4 と一緒に）。

### 3-3. 重複申請の禁止

| 決まり | 出どころ |
|---|---|
| **承認待ちの申請がある拠点は、新しい申請で選べない**（「申請中」と表示してグレー）。**解約も例外にしない**。急ぐときは取り下げてから申請し直すか、お問い合わせ | 28-4 |
| 承認待ちのあいだは、法人Web の承認必須の欄も止める | 法人Web §1・§4-3 |
| 承認待ちのあいだは、運営もその拠点の子契約で申請の対象項目を直接編集できない | TL-1、契約_01 §1 |
| 代理入力も同じ（承認待ちのある拠点は選べない） | 28 §8 案、28-144⑨ |
| 休止の予定が承認済みの拠点は、プランの変更・休止を選べない | 法人Web §2-2 |
| 文言：「承認待ちのお申し込みがあるため、承認後にお申し込みください。」 | 入力チェック仕様 §4 |

### 3-4. 取り下げ

| 決まり | 出どころ |
|---|---|
| **運営がまだ処理していない拠点に限り**、法人Web の「申請中の内容」から拠点ごとに取り下げられる。処理済みの拠点は不可 | 28-26 |
| 取り下げられるのは**申請を出したアカウントと法人アカウントだけ**。拠点アカウントで法人アカウントが出した申請を開くと「取り下げる」を出さず「法人アカウントが出した申請のため、取り下げは法人アカウントから行います」 | H2、法人Web §1 |
| 取り下げ日時を残す（法人Web の申請履歴に出す） | 28-28、契約_04 |

### 3-5. 却下

| 決まり | 出どころ |
|---|---|
| **却下理由は必須**（定型の選択肢＋自由記述）。**法人へ拠点ごとに通知**し、理由の定型文を載せる | 28-25 |
| **差戻しは作らない**（直したいときは申請し直す） | 28-25（9/11） |
| 定型の選択肢（今の画面）：申請内容に不備がある／オーダー締切に間に合わない／設備・在庫の手配ができない／配送エリア・配送ルートの都合で対応できない／契約条件（最低利用期間など）に合わない／その他（下に詳しく書く） | `lib/ops/applications/constants.ts`（決定ファイルに一覧はない） |
| 却下された申請は法人Web のマイページ（申請の一覧）に「お受けできませんでした」と理由を出す | 28 §6、メール一覧 M6 |

### 3-6. 承認前の設定と承認のチェック

| 決まり | 出どころ |
|---|---|
| 申請詳細に「影響と設定」タブを置き、拠点ごとに **承認すると動くもの** と **承認の前にする設定** を出す。**必須の設定が終わるまでその拠点は承認できない** | 28-144① |
| 承認前の設定は**承認必須の項目だけ** | STEP1（10/01 夜） |
