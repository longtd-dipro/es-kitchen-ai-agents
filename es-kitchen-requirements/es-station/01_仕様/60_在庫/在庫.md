## 1. 言葉

| 言葉 | 意味 |
|---|---|
| 倉庫在庫 | ピッキング倉庫（関東・関西〈THOMAS〉・ES事務所）にある数 |
| 拠点在庫 | お客様の拠点の冷蔵庫・自販機にある数。**拠点ごと**に持つ |
| 理論在庫 | システムが計算した拠点在庫（納品 − 購入 − 廃棄 ± 調整）。**マイナスになってよい** |
| 実在庫 | 棚卸しで数えた数 |
| 仮確保 | 注文（支払い前）で押さえている数 |
| 利用可能在庫 | 理論在庫 − 仮確保 |
| 棚卸報告 | 拠点の在庫点検の申告（画面の名前。旧「在庫点検の申告」） |
| 管理ロス | 理論在庫 − 実在庫（お金に直して、免責金額を超えた分を請求） |

## 3. 拠点在庫の増減

| 増える | 減る |
|---|---|
| 納品（便ごとに**足していく**。リセットしない） | 個人アプリ・ESQR の購入（支払い完了） |
| 在庫の移動で入る（運営） | 廃棄の登録 |
| 運営の在庫調整（＋） | 在庫の移動で出る・運営の在庫調整（−） |

- 棚卸しの締めのあと、**理論在庫を実在庫で上書き**し、次の期の始まりにする（REQ-PO-418b）。
- 棚卸しの日より後に届いた便は、**次の棚卸しに入れる**（課題一覧 4a-11・2026/10/03）。
- 賞味期限・ロットは便ごとに持つ。
- **新システムへ切り替えるとき**：購入はロックしない。理論在庫は 0 から始め、前から残っている商品はスキャンで買える。法人Web に「最初の棚卸報告をしてください」と、報告するまで出す。**切り替えたあとの最初の棚卸報告までは管理ロスを出さない**（台帳 N・hong 2026-10-05）。

## 4. 個人アプリ・ESQR の購入と在庫（要点）

詳しい動き・図・例は `Flow tồn kho_for dev.md`。

| # | 決まり |
|---|---|
| 4-1 | カートに入れただけでは在庫を動かさない。**注文（支払い前）で仮確保**、**支払い完了で理論在庫を引く** |
| 4-2 | 支払い待ちは **30分**（約15分ごとに通知）。過ぎた・失敗・キャンセル → 仮確保を外す |
| 4-3 | 支払い完了のあとの返金（不良品など）では、**理論在庫を戻さない**（棚卸しで直す） |
| 4-4 | メニュー・購入履歴・お気に入りからの購入数は、**利用可能在庫まで** |
| 4-5 | **スキャン購入は例外**：1回1個・数量は変えられない・在庫を確かめない（実物があるとみなす）。理論在庫はマイナスになってよい |
| 4-6 | 利用可能在庫が0以下：メニューには**出さない**／購入履歴・お気に入りには出すが「次回の登場をご期待ください。」で、詳細もカートも不可／スキャンでは買える。カートの中の品切れ商品はアプリを開き直したときに消す |
| 4-7 | **「残りわずか」**：しきい値＝切り捨て（その拠点の注文数 × 残りわずか率）。利用可能在庫 > 0・しきい値 ≥ 1・利用可能在庫 ≤ しきい値 のとき出す。率はプランマスタでプランごと。残りの数は見せない。法人は ON/OFF できない。「プラン100以下は出さない」決まりはやめた |
| 4-8 | 運営が「キャンセル」を「支払い済み」に手で直すときは、理由が必須・ログを残す |

## 6. 管理ロスと実績精算

| # | 決まり | 根拠 |
|---|---|---|
| 6-1 | 管理ロス＝（理論在庫 − 実在庫）を、**価格調整の前の標準の価格**でお金に直す。プランの**免責金額**（例：100プランで300円）を超えた分を請求する。範囲の中は ES の負担 | REQ-PO-415 |
| 6-2 | 賞味期限切れの廃棄は、原則として請求しない | REQ-PO-416 |
| 6-3 | 実績精算の内訳は3つ：**管理ロス・現金回収差額・価格調整差額**。内訳ごとに確定し、3つとも必須（対象なしも確かめて確定）。在庫調整は任意 | 28-144 ⑤・28-145 ⑦ |
| 6-4 | 実績精算を確定した月は、在庫調整を編集できない。あとで見つかった誤りは翌月の実績精算で相殺する | 28-121 |
| 6-5 | 在庫・棚卸報告・実績精算は、確定したときに**月ごとの写し**を保存し、過去の月はそれを参照だけで出す | 28-125 |
| 6-6 | 請求のしかた（時期・書類）は `40_マスタ・料金・請求/請求ルール_仕様_v1.md` | — |

## 7. 運営の在庫管理（拠点在庫）

| # | 決まり | 根拠 |
|---|---|---|
| 7-1 | メニューは「在庫管理」。一覧＝在庫一覧、詳細＝在庫詳細（棚卸報告の結果：状態・申告日・申告者・方法）、編集＝在庫調整 | 28-120 |
| 7-2 | 棚卸の前は計算在庫だけ、棚卸の後は申告の数と差（管理ロス）も出す | 28-119 |
| 7-3 | **在庫調整は運営のシステム管理が手で行う**：拠点の間の在庫の移動（移動元 −／移動先 ＋）、破損・不良品の交換。**理由は必須・履歴に残す**（登録者が分かる）。**保存したらすぐ反映**（申請・承認なし）。法人からの返品による調整はしない。**別の法人の拠点をまたぐ移動はお客様が自分で動かし、システムは費用を計算しない**（台帳 N） | REQ-PO-419・419b・601、28-121 |
| 7-4 | 拠点を複数選んで**まとめて在庫調整**できる | 28-126 |
| 7-5 | **差分率**＝（理論 − 申告）÷ 理論。**絶対値が10%以上**で色を付ける（マイナスも）。**廃棄率＝廃棄 ÷（前回の在庫 ＋ 納品）**（どの画面でもこの式・台帳 H）も 10% 以上で色を付ける。出す画面は**在庫調整と実績精算の確定**の2つ。しきい値は当面 10% で固定 | 課題一覧 2-1・4a（2026/10/02・10/03） |
| 7-6 | 請求の候補は運営が確かめる。警告のない行は**複数選んでまとめて確定**できる | 課題一覧 2-1、28-127 |
| 7-7 | 対象月を選べる（初期値＝当月。過去の月は参照だけ）。検索：対象月・法人・拠点・棚卸（前・後）・実績精算（確定・未確定） | 28-120 |
| 7-8 | 販売の数＝アプリで売れた数から返金済みを引いた数 | 課題一覧 4a-3（2026/10/03） |
| 7-9 | 廃棄率が3%を超えたら、ダッシュボードにアラート（ポップアップは出さない） | REQ-PO-416 |
