## 第II部　補足

### ID体系（2026/09/15 確定）

| 対象 | 形式 | 例 | 型 |
|---|---|---|---|
| 法人ID | `CU` ＋ 連番（最小5桁） | `CU00001` | varchar(20) |
| 拠点ID | `CU` ＋ 連番（最小5桁） | `CU00643` | varchar(20) |
| 契約ID（親契約） | `CP` ＋ 連番（最小6桁） | `CP000001` | varchar(20) |
| 子契約ID | 契約ID ＋ `-yyyymm`（**契約・サイクル月**） | `CP000001-202607` | varchar(30) |
| プランID（プランマスタ） | `ES` ＋ 連番（最小6桁） | `ES000012` | varchar(20) |
| 機種ID（機種マスタ） | 機種区分2文字 ＋ 連番（最小6桁）。RF／FZ／VM／MW／HW／BX（旧：FZ なし。2026-10-03 マスタ ⑫-3 に合わせて修正） | `RF000001` | varchar(20) |
| **オプションID**（オプションマスタ） | `OP` ＋ 連番（最小6桁） | `OP000001` | varchar(20) |
| **値引きID**（値引きマスタ） | `DC` ＋ 連番（最小6桁） | `DC000001` | varchar(20) |
| ~~**適用ID**（拠点のオプション・割引）~~ | **廃止**：オプション・割引は子契約が持つ（28-144/145）。1行は「子契約ID＋オプション／値引きコード」で特定する。`AP-` は新規申込の受付番号だけに使う〔hong 回答 2026-10-03（K7＝A）〕 | ~~`AP-0001`~~ | — |

> 子契約ID の `-yyyymm` は確定。**yyyymm は子契約の契約月（サイクル月）**〔hong 回答 2026-10-03（K6）〕。

桁数は固定しません。接頭辞＋連番というフォーマットさえ守れば、件数が増えたときに桁が増えて構いません。
一意キーは **`UNIQUE(親契約, 契約・サイクル月)`** です。請求月は法人の請求書発行リードタイムで別に決まるため、子契約IDから請求月は読み取れません。

### 2026/09/25 に決まったこと

| 項目 | 決定 |
|---|---|
| 拠点ごとの請求書発行リードタイム | **拠点ごとの上書きを許す**。「請求書発行リードタイムの上書き」は残す |
| 値引きの重ねがけの順番 | **値引きごとに適用順を入力する** |
| 連動タイプAの効き始める月 | オーダー締切（既定 前月15日）までの変更は翌月の子契約から、過ぎたら翌々月から料金を立てる（旧：翌月の子契約から。2026-10-03 契約_01 §4 に合わせて修正）。オプションマスタの「効き始める月」は持たない |
| 請求書一覧を法人Webに出すか | **出す**（子契約の「料金・請求」タブは引き続き出さない） |
| 入金状況の取り込み | Bill One から**取り込まない**。請求書一覧に入金状況の列は持たない |
| 実績精算（②）の締めと請求月 | **20日締め・25日確定・翌月1日に送付。請求月はサイクル月の翌月**（6/21〜7/20 は 8/1 送付の請求書） |
| 金額の持ち方 | **税抜＋税率**で持ち、消費税は請求書で税率ごとに上乗せ（プラン・機種・オプション・値引きとも） |
