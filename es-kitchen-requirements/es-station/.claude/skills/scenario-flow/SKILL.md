# シナリオを本物の Web で動かして、クリックで進むビューアにする

ユーザーは文字の多い資料を読まない（読んでもすぐ思い描けない）。だから成果物は**画面の画像と赤い枠（押す場所）とデータのチップ**が主役で、文字は1ステップ1行。

## できるもの
`<出力先>/` に2つ：`<id>_<題名>.html`（**閲覧用**。画像を縮めて WebP で埋め込み、500KB 未満の1ファイル。Claude アプリの Browser ペインは 512KB までなのでこちらを開く）と `<id>_<題名>_送付用.html`（元の画質で埋め込み。メール・チャットで送る用）。出力先はセッションのフォルダの中（ES なら `ÉS/Claude outputs/シナリオ/<id>/`）にする。スクラッチパッドに置くとアプリで開けない
- 上：サイトごとのレーン（法人Web／運営／倉庫／ドライバー…）に、ステップの番号の丸。流れがサイトをまたぐ様子が見える
- 左：本物の画面。押す場所は**赤い枠が点滅＋「ここを押す」**。押すと次のステップへ。ほかを押すと枠が揺れて教える。見るだけのステップは青い点線の枠＋「次へ」
- 右：このステップで**変わったデータ**（ID・種類・新規／更新・状態 前 → 後）と、ここまでに出てきた ID の並び（例 AP-… → CU… → CP… → DL-… → INV-…）
- 各ステップに ✅ 動いた／⚠ 要確認（データが変わらない等）／❌ 動かない（ボタンがない等）

## 動かし方
```bash
python3 <スキル>/scripts/run.py <スキル>/scenarios/s00_基本の流れ.json --out <出力先>
```
1. 共有の DB `07_開発/data/es.db` を**読み取り専用でコピー**し、そのコピーを `ES_DB_FILE` で指した `next start`（ポート 3300）を立てる。共有の DB は変わらない。終わったらサーバーを止め、コピーを消す
2. マシンの Google Chrome（見えない状態）でステップを順に操作し、押す前の画面・押す場所・押す前後の DB の差を記録する
3. ビューアを作る

**守ること**
- サーバーは1つずつ（Mac 8GB）。ほかに `next dev`／`next start` が動いていたら、止めてよいかユーザーに聞く（ほかのセッションのものかもしれない）。デモ・打ち合わせの前後は動かさない
- `next start` は最後の build で動く。**build が古いと、画面は動いても DB に書かれない等、今のコードと違う結果になる**（2026-10-03：10/02 の build では法人の月次注文が DB に保存されなかった）。`.next/BUILD_ID` の日時と最新コミットを比べ、古ければ先に build（重いのでユーザーの了解を取る。`nice -n 15 npm run build`）
- `--base-url` で既存のサーバーを使うと、そのサーバーの DB が変わる。共有 DB を使っているサーバーには使わない
- ログインに使う ID・パスワードは、開発用の見本の値（`lib/corp/session.ts` などの seed）だけ。本物のアカウントは使わない

## シナリオの書き方（scenarios/*.json）
```json
{"id": "s00", "title": ["日本語", "Tiếng Việt"], "goal": ["…", "…"], "source": "元にした資料",
 "steps": [
   {"site": "corp", "url": "/corp/order",
    "cap": ["1行の説明（日本語）", "1 dòng (tiếng Việt)"],
    "fill": [{"sel": "input[name=q]", "value": "10"}],
    "click": ["button:has-text('登録')"],
    "confirm": ["button:has-text('登録する')"],
    "expect_change": ["月次注文が保存される", "Order được lưu"],
    "watch": ["CP0000002-202611"]},
   {"site": "ops", "url": "/ops/delivery/schedule", "cap": ["…", "…"], "look": ["main table", "main"]}
 ]}
```
- `site`：corp／ops／warehouse／driver／carrier／supplier／system（レーンになる）
- `click`（押す）か `look`（見るだけ・枠を出す場所）。セレクタは Playwright の書き方（css、`text=…`、`button:has-text('…')`）。リストなら最初に見つかったもの
- `cap` は**1行**。説明を足したくなったら、ステップを分ける
- `expect_change`：データが変わるはずのステップ。変わらなければ ⚠
- `confirm`：押したあとに出る確認モーダルのボタン
- 元にするシナリオ：`00_確認してほしい/作業記録_20261003/シナリオ実行チェックリスト_20261003.md`（URL・操作・データ）、`01_仕様/90_デモ確認/シナリオ説明書_生成/data/s*.json`（説明文）

## 直すとき
- ❌（見つからない）→ 出力の画像を見てセレクタを直し、もう一度 run
- ⚠（データが変わらない）→ 本当に動かないのか（機能がない・データ不足）を確かめ、ユーザーに報告。シナリオの側を勝手に変えない
- 結果の報告は、ビューアのファイルと「✅ n／⚠ n／❌ n」と ⚠❌ の一覧だけ（長い文章にしない）

## ファイル
- `scripts/run.py` — DB のコピー・サーバー起動・ブラウザ操作・DB の差・後片付け
- `scripts/viewer.py` — result.json からビューア（HTML）を作る（`python3 viewer.py <出力フォルダ>` で作り直しだけもできる）
- `scenarios/` — シナリオ
