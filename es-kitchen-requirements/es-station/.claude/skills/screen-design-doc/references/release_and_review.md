# 開発に渡す（版をつける）
**版の決まり（ユーザーの決定 2026-10-03）**：0.x＝社内の下見（開発に渡さない）／**1.0＝そのサイトのファイルを初めて開発に渡すとき**（機能が1つでも）／
渡すたびに +0.1（機能の追加も、渡した機能の直しも）／**2.0＝お客様がサイト全体を正式に承認したとき**。
```bash
python3 scripts/make.py --release 1.0 --book 法人Web <作業>/データ/CW_*.py
python3 scripts/make.py --release 1.1 --book 法人Web <作業>/データ/CW_*.py   # 2回目以降
```
- `--release` は前回渡した版（`出力/<ブック>/_release/snapshot.json`）とデータを比べ、変わった項目が各データの `CHANGES`（その版）に書かれていなければ止める
- 直したら `CHANGES` に1行：版・日付・項目No（機能ごと追加は "*"）・追加／変更／削除・変更前→変更後・理由・**開発への影響**（日本語・ベトナム語）
- Excel には「改訂履歴」シート（新しい版が上、今回の版は黄色）と、機能シートの「変更」列（今回変わった行はオレンジ）が出る
- 小さな直しは1日分まとめて1つの版にする（開発に何度も渡さない）
