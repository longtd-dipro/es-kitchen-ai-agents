# 決定と仕様（ES STATION）

- **いま有効な決定は `docs/決定台帳.md` が正。** 提案・質問・実装の前に必ず読む。仕様書と食い違ったら台帳が正（仕様書の直し漏れ）。
- 仕様書は `docs/01_仕様/`（話題別）と `docs/議事録_仕様/`。`docs/01_仕様/00_決定/` の46ファイルは **凍結（経緯を見るだけ）**。中身の行き先と、置き換えられた決定は台帳「G」。古い決定ファイルから提案しない。
- ユーザー（hong）の新しい回答が台帳と違うときは、「○/○ に △ と決めています。□ に変えますか？」と確認してから変える。勝手にどちらかを選ばない。
- 新しい回答は、**同じコミット／PR の中で** `docs/決定台帳.md` に書く（古い答えは「置き換えた旧決定」へ）。
- 「凍結（原典）」と書かれた仕様ファイルは直さない。正のファイルを直す。
- 台帳にも仕様にもないことは推測しない。「要確認」としてユーザーに聞く。
- cloud では `00_確認してほしい/`・議事録の原本・Excel・画像は見えない（ローカルのみ）。
- **会議の決定は `docs/決定の受付簿.md` を通す。** 仕様・台帳を直接直さない。hong が「採用」にした行だけ台帳と仕様へ反映し、状態を「実装待ち」にする。コードを直したら「実装済」とコミットを書く（cloud でも同じ）。
- 画面の点検・実装の正は台帳と仕様だけ。フェーズ1 の画面写真・Figma・機能一覧・旧デモは参考で、正ではない。台帳に決定がない点は参考に合わせて決めず、hong に聞く。
