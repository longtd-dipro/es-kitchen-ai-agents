# 購入・決済・返金

> **この話題の正。** 2026-10-09 までに確認した購入・決済・返金の決定を、画面・決済会社 API・在庫・集計をまたぐ仕様としてまとめた。
> いま有効な決定は `docs/決定台帳.md`。食い違ったら台帳が正。

## 1. 対象と識別子

| # | 決まり |
|---|---|
| 1-1 | 個人アプリ、ESQR、ゲストの購入を同じ購入データとして扱う。購入元は区別して保持する |
| 1-2 | 注文番号は `OD`＋7桁。1注文に複数商品がある場合、商品行は複数でも注文番号は同じ |
| 1-3 | 返金の単位は商品行ではなく**注文全体（OD番号）**。同じ注文の一部の商品だけを返金しない |
| 1-4 | ESQR・ゲストにも通常のユーザーと同じユーザーIDを持たせる。正式なアカウント・メールは持たず、性別・年代は保持しない |

## 2. 購入と在庫

| # | 決まり |
|---|---|
| 2-1 | カート投入では在庫を動かさない。注文作成（支払い前）で仮確保し、支払い完了で購入元拠点の理論在庫を減らす |
| 2-2 | 支払い待ちは30分。期限超過・失敗・キャンセルでは仮確保を外す |
| 2-3 | スキャン購入は1回1個で、在庫を確認しない。理論在庫はマイナスになってよい |
| 2-4 | 返金成功時の在庫の扱いは §4。返金失敗・結果不明では在庫を変えない |

## 3. 返金できる条件と入力

| # | 決まり |
|---|---|
| 3-1 | 返金を実行できるのは運営Webのフル権限だけ。法人Webは参照のみ |
| 3-2 | 返金可能期間は支払い完了日から3か月（暫定）。今日を含めて判定する。決済会社の取消期限が判明したら見直す |
| 3-3 | 理由は「注文が重複している」「注文を間違えた」「商品が品切れだった」「商品に不具合があった」「その他」の5択 |
| 3-4 | 「その他」を選んだ場合は備考（複数行、500文字以内）を必須にする |
| 3-5 | 返金対象は注文全体。確認画面には注文番号、対象商品、数量、返金額、決済方法、理由を出す |

## 4. 返金の実行と状態

| # | 決まり |
|---|---|
| 4-1 | 画面の「返金」で、対象注文の決済会社の返金 API を即時に呼ぶ |
| 4-2 | API の応答待ちの間だけ「返金中」とする。「返金中」は永続的な完了状態ではない |
| 4-3 | API が成功したら、同じ注文の全商品行を「返金済」にし、返金日時・理由・決済会社の参照情報を記録する |
| 4-4 | 成功時は、同じ注文の各商品の購入数量を購入元拠点の理論在庫へ自動で加算する |
| 4-5 | 「返金済」への更新と在庫加算は、1つの成功処理として記録する。一方だけを成功させない |
| 4-6 | API が失敗または結果不明なら、購入の確定状態を変えず、在庫も変えない。エラーの日時・対象注文・内容を記録し、画面に表示する |
| 4-7 | 失敗時は運営が再実行できる。結果不明時は決済会社側を手動確認してから再実行または状態を確定する |
| 4-8 | 二重クリック、再送、同時操作でも、同じ注文の返金 API と在庫加算を二重実行しない。注文番号に結び付く一意な返金実行キーで冪等に扱う |

## 5. 集計・表示・CSV

| # | 決まり |
|---|---|
| 5-1 | 購入数・購入金額は「支払済」と「返金中」を含み、「返金済」を差し引く。「キャンセル」は含めない |
| 5-2 | 返金回数・返金金額は「返金済」だけを数える。「返金中」、失敗、結果不明は数えない |
| 5-3 | KPI、合計行、一覧、CSV、運営Web、法人Webの購入・ユーザー管理で §5-1・§5-2 の定義を共通で使う |
| 5-4 | 状態の表示とCSV値は「支払済」「返金中」「返金済」とし、「〜済み」は使わない |
| 5-5 | 失敗・結果不明は購入状態とは別の返金実行履歴として表示する。購入を「返金済」に見せない |
| 5-6 | 法人Webの購入一覧・ユーザー別の購入には、**キャンセル、ESQR、ゲストの購入を出さない**。法人・拠点は自分の拠点の会員（アカウントを持つ購入者）の購入だけを見る。期間の既定は当月（1日〜今日）（2026-10-15 hong 回答・台帳 AK SALE-Q1・Q2。画面の細部は `80_運営・法人の画面/運営・法人の画面.md` §2-8〜2-11） |

## 6. 処理境界と記録

返金 API の呼び出し自体と、成功後のシステム内更新は同じデータベーストランザクションにはできない。そのため、少なくとも次を注文単位で記録する。

| 記録 | 用途 |
|---|---|
| 返金実行キー | API の再送・二重操作を同じ返金として扱う |
| 注文番号・決済ID・決済方法 | 決済会社側との照合 |
| 要求日時・応答日時・結果 | 成功、失敗、結果不明の追跡 |
| 返金額・理由・備考・実行者 | 監査と画面表示 |
| 在庫反映日時 | 返金成功後の在庫加算が1回だけ完了したことの確認 |

決済会社から成功を受けた後は、注文の「返金済」更新・在庫加算・返金実行履歴の確定を、システム内の1トランザクションで行う。途中で失敗した場合は成功済みとして確定せず、安全に同じ処理を再開できるようにする。

## 8. 受入条件

- 同じOD番号に複数商品があっても、1回の操作で注文全体だけが返金される。
- 成功時だけ、全商品行が返金済になり、各数量が購入元拠点の理論在庫へ1回だけ加算される。
- API失敗・タイムアウト・結果不明では、返金済にも在庫加算にもならず、原因を確認できる。
- 同じ操作を再送・同時実行しても、返金額と在庫が二重にならない。
- 返金中は購入数・購入金額に含まれ、返金済だけが購入数・購入金額から引かれる。
- 運営Web・法人Web・CSV・KPI・合計行で同じ値になる。
