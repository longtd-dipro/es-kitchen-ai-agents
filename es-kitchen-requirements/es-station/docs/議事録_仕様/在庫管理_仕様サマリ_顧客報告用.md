# ES在庫管理 仕様サマリ（デモ・顧客報告用）

対象：ユーザーアプリ／ESQR の購入時在庫ロジック、拠点在庫、棚卸し、メニュー表示（フェーズ2）
出典：定例会（2026/07/31・08/21・08/25・09/01・09/02・09/04 ほか）での決定事項、hong 回答 2026/09/30（K-15・K-20）

---

## 1. 在庫仕様サマリ（決定事項一覧）

| No. | カテゴリ | 決定事項（仕様） | 例・補足 |
|---|---|---|---|
| 1 | 在庫の引き当てタイミング | カート追加：**引き当てなし**／注文（支払い前）：**仮確保**／支払い完了：**理論在庫を正式に減算** | 支払い前は他ユーザーの重複購入を防ぐため仮確保のみ |
| 2 | 支払い待ちの保持時間 | **30分**（従来6時間から短縮）。超過・失敗・キャンセルで在庫を戻す。約15分ごとに通知 | 例：最後の在庫を注文→30分未払いなら自動解放 |
| 3 | 返金と在庫戻し | 支払い**前**のキャンセル／失敗／30分超過 → **在庫を戻す**。支払い**完了後**の返金（不良品等）→ **理論在庫は戻さない**（棚卸しで補正） | 商品は拠点の冷蔵庫内。判定基準は「支払い状態」 |
| 4 | 在庫調整（手動） | **System adminのみ**手動調整（①拠点間の在庫移動 ②不良品の交換）。理由入力必須＋ログ保存。**法人からの返品運用はなし** | 拠点間移動：移動元−／移動先＋ |
| 5 | 理論在庫のマイナス | スキャン購入・手動調整によりマイナス許容。**実在庫を優先**し、棚卸しで補正 | 品切れでも実際に在庫があればスキャンで購入可 |
| 6 | 品切れ表示（理論在庫≤0） | **メニュー画面：非表示**／**購入履歴・お気に入り：「次回の登場をご期待ください。」を表示（詳細遷移・カート追加不可）**／**スキャン購入は可** | カート内の品切れ商品はアプリ再起動時にクリア |
| 7 | 「残りわずか」バッジ | しきい値＝**切り捨て（拠点の発注数 × 残りわずか率）**。理論在庫>0 かつ しきい値≥1 かつ 理論在庫≤しきい値 で表示 | 発注12・率25%→しきい値3（残り3で表示）。発注3→0で非表示 |
| 8 | 残りわずか率の設定 | **プランマスタでプラン／コースごとに設定**（コード固定しない）。在庫の具体数は非表示。法人トグルなし。「プラン≤100非表示」ルールは廃止 | 率の値は運用時にマスタで調整 |
| 9 | 拠点在庫の管理単位 | **拠点ごと**に在庫管理。購入は拠点ID／QRで拠点を識別し当該拠点在庫を減算。購入数量上限＝理論在庫 | ゲスト／拠点ID未登録：スキャンのみ・標準価格・購入前に拠点ID入力 |
| 10 | 棚卸し | 月1回、**21日〜翌20日**。法人担当者またはES配送ドライバーが実施。モバイル対応・PDF出力。**理論在庫は非表示、実在庫のみ入力**（点検表も同じ。実施者が法人・ES配送ドライバーのどちらでも同じ）。ES配送便ドライバーは**納品時の在庫・廃棄確認（STEP2）では理論在庫を見られる**（2026/09/30 変更。旧：STEP2 との関係の記載なし） | 週次リマインド。25日まで未実施→**管理手数料3,000円** |
| 11 | 棚卸し値の用途 | 提出値を①**管理ロス算出**、②**締め後に理論在庫へ上書き**（翌期の起点） | 理論5・実3提出→ロス2、締め後理論在庫=3 |
| 12 | 管理ロスの請求 | プラン許容範囲を超えた分を請求（例：100プラン=300円）。範囲内はES負担。単価は標準価格 | 賞味期限ロスは原則請求対象外／廃棄率>3%でアラート |
| 13 | メニュー表示（フェーズ2） | **公開商品を「拠点在庫>0」でフィルタ表示**（在庫のない商品は非表示）。フェーズ1は公開予定日で2ヶ月分表示（在庫連動なし） | フェーズ2で在庫連動へ移行 |
| 14 | 出荷ごとの在庫 | 在庫は**出荷（ship）ごとに管理し合算**（リセットしない）。賞味期限／ロットも出荷ごとに管理 | 前半10・6個購入で残4＋後半10＝**合計14** |
| 15 | 在庫戻し（自社への返送） | 商品オーダーの**手動新規作成は持たない**。棚卸し後に翌月使わない商品を自社へ戻す出荷は、**発注を伴わない出荷指示を作る専用画面**で登録し、トーマスへ CSV で出す（2026/09/30 追加） | 営業サンプル・試験用サンプルは契約経由のまま |

## 2. 主要パラメータ

| パラメータ | 値 |
|---|---|
| 支払い待ち保持時間 | 30分 |
| 支払い通知 | 約15分ごと |
| 棚卸し期間 | 21日〜翌20日 |
| 締め日 | 25日 |
| 棚卸し未実施の事務手数料（2026/10/02 呼称変更。旧：ペナルティ） | 3,000円 |
| 管理ロス請求しきい値 | プラン別（例：100プラン=300円） |
| 廃棄率アラート | 3%超 |
| 冷凍上限 | プランでの個数（プランマスタの冷凍の月次提供数）で決める（2026/09/30 変更。旧：プランの30%以内） |
| 残りわずか率 | プランマスタで設定（プランごと・可変） |
| 購入数量上限 | 理論在庫まで |

## 3. 業務の流れ（1ヶ月サイクル）

発注 → 出荷（複数回・在庫合算）→ アプリ購入で在庫減算 → 棚卸し（21〜20日）→ 25日締め（管理ロス算出・理論在庫を実在庫で上書き）→ 翌期へ
