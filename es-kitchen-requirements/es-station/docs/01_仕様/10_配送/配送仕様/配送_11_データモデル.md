## 14.4 区間（delivery legs）

ルートは**別々のテーブル**で持つ。`contract_routes`／`contract_month_routes` は定義と月ごとのスナップショット（14.2）、`delivery_legs` は配送1件ごとの実際の区間。

| テーブル | 列 | 備考 |
|---|---|---|
| `delivery_legs` | `id, delivery_id, leg_no, from_type(warehouse｜relay), from_id, to_type(relay｜destination), to_id, carrier_id, temp_type, delivery_regime, is_final_leg, driver_id NULL, assign_scope(ops｜carrier), assigned_by NULL, assigned_at NULL, picked_up_at NULL, picked_up_by NULL, snapshot_source(contract_month｜contract), snapshot_at` | 配送データ1件の実際の区間。ドライバーの割当（`driver_id`）は**ここにだけ**ある。`picked_up_at`／`picked_up_by`＝その区間での荷物受取の時刻・受取者（DEV §13.1） |

```sql
UNIQUE(channel_id, leg_no)            -- contract_routes
UNIQUE(channel_id) WHERE is_final_leg
UNIQUE(month_channel_id, leg_no)      -- contract_month_routes
UNIQUE(month_channel_id) WHERE is_final_leg
UNIQUE(delivery_id, leg_no)           -- delivery_legs
UNIQUE(delivery_id) WHERE is_final_leg
```

**3テーブル共通の guard**

| # | 規則 |
|---|---|
| 1 | `leg_no` は 1 からの連番で、飛ばさない |
| 2 | leg 1 は `from_type = warehouse` かつ `from_id = channel.warehouse_id` |
| 3 | leg `n+1` の `from_id` ＝ leg `n` の `to_id` |
| 4 | `is_final_leg = true` の leg はちょうど1本で、その leg は `to_type = destination` |
| 5 | 中継なし＝1レグ、中継あり＝2レグ（フェーズ2） |
| 6 | 画面の配送会社①②は常に両方必須。途中経由は「なし」を明示して選ぶ（既定「なし」）〔hong 回答 2026-10-03・REQ-DL-710〕。【要確認・開発】中継なし（①＝②の同じ会社）のとき、②をレグ1本の `carrier_id` に畳むのか、別に持つのか |

**`delivery_legs` だけの規則**

| 規則 | 内容 |
|---|---|
| いつ作るか | 確定生成（materialize）のとき。子契約があれば `contract_month_routes` から、無ければ `contract_routes` から写し、写した元を `snapshot_source` に残す（DEV §8.1） |
| 最終区間の行き先 | 最後の leg の `to_id` ＝ スナップショット済みの `deliveries.site_id` |
| 不変 | **写したあとは変えないスナップショット。** `contract_routes` を直しても作成済みの配送データには効かない |
| この配送だけのルート変更 | その配送の `delivery_legs` を直接直し、監査に残す（API 仕様 15.13）。**上書き用の別の列は持たない** |
| 複製 | leg を全部コピーするが、`driver_id`・`assigned_by`・`assigned_at` はコピーしない（DEV §9.4）。`picked_up_at`・`picked_up_by` もコピーしない（`配送_09` §16-3） |
| 割当の単位 | `contract_routes`・`contract_month_routes` は `driver_id` を持たない。ドライバーの割当は配送データの単位にしか無い |

## 14.13 月ごとのスナップショット：在庫・棚卸報告・実績精算（追補7・2026-09-29）

決定：申請まわり 28-121・28-125。運営の画面（在庫管理／実績精算／請求の確定）は**前の月も見られる**。確定した月は**スナップショットだけを読み**、今のデータから計算しなおさない。

| 項目 | 規則 |
|---|---|
| 期間 | 子契約の `cycle_month` で持つ。在庫の期間＝前月21日〜当月20日 |
| 在庫調整 | 運営が直接入れる。**承認なし**、保存した時点で計算在庫（`calc_qty`）に**すぐ効く**。入れられるのは実績精算（`settlement_snapshots`）が**未確定**の月だけ。理由必須。複数の拠点に同じ理由でまとめて入れられる |
| 確定のあと | その月の調整は直さない。あとで見つかった誤りは**翌月**の `settlement` に `invoice_lines.line_type = adjustment` の行で入れる（DEV §13.7） |
| 棚卸報告 | 拠点 × 月で1件。商品別の数。25日までに報告が無くても確定できるが、事務手数料がかかる（請求側の決まり） |
| 実績精算の確定 | 確定のとき、`monthly_stock_snapshots`（商品別）と `settlement_snapshots`（合計）を**1つのトランザクション**で書く。翌月の `prev_counted_qty` ＝ 今月のスナップショットの `counted_qty` |
| 確定の取り消し | その子契約の請求書がまだ無いときだけ。古いスナップショットに `unconfirmed_at` を入れる（消さない）。もう一度確定したら新しいスナップショット。画面は `unconfirmed_at IS NULL` を読む |

| テーブル | 列 | 備考 |
|---|---|---|
| `stock_counts` | `id, site_id, contract_month_id, cycle_month, period_from, period_to, status(not_filed｜filed), filed_at NULL, filed_by NULL, filed_via(driver_app｜corp_web) NULL` | 棚卸報告（画面名も「棚卸報告」。「在庫点検の申告」は使わない〔hong 回答 2026-10-03〕） |
| `stock_count_lines` | `id, stock_count_id, product_id, counted_qty` | 棚卸報告の商品別の数 |
| `stock_adjustments` | `id, site_id, cycle_month, product_id, delta_qty, reason, bulk_id NULL, created_by, created_at, cancelled_at NULL` | 在庫調整（運営・承認なし・すぐ効く）。`bulk_id`＝複数の拠点にまとめて入れたときの束 |
| `monthly_stock_snapshots` | `id, contract_month_id, site_id, cycle_month, product_id, prev_counted_qty, delivered_qty, sold_qty, disposed_qty, adjusted_qty, calc_qty, counted_qty NULL, loss_qty, unit_price, loss_amount, snapshot_at, unconfirmed_at NULL` | 実績精算の確定で書く |
| `settlement_snapshots` | `id, contract_month_id, cycle_month, sales_amount, loss_amount, deductible_amount, over_amount, price_adjust_diff, admin_fee, settlement_amount, cash_expected_amount, cash_collected_amount, cash_diff_amount, confirmed_at, confirmed_by, unconfirmed_at NULL` | 食事補助の金額は持たない（企業負担額はプランの価格に入っている・28-134）。`cash_*`＝アプリで現金払いを選んだ分だけ（28-135）。**駐車料金は入れない**（台帳） |

```sql

UNIQUE(stock_count_id, product_id)                                     -- stock_count_lines
UNIQUE(contract_month_id, product_id) WHERE unconfirmed_at IS NULL     -- monthly_stock_snapshots
UNIQUE(contract_month_id) WHERE unconfirmed_at IS NULL                 -- settlement_snapshots
```

- `delivered_qty` は期間内の配送データの `delivery_lines.delivered_qty` から取る（14.7）。`sold_qty` はアプリの販売データから（本書の範囲外。商品別の合計だけを受け取る）。
- 法人ごとの確定（法人確定・28-123）はもう無い。確定は子契約の単位だけ。
- 【要確認】`monthly_stock_snapshots` の UNIQUE が `(contract_month_id, product_id)` で `site_id` を含まない。子契約＝拠点1つが前提なら問題ないが、確認が要る。
