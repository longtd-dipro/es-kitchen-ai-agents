# ドライバーアプリ（Driver Mobile Web P2）仕様修正点 — 2026/09/30

Figma「Driver Moblie Web (P2)_review 可」と配送仕様（統合仕様書 v2.3 §12-2・§13-1、納品サイクル設定 §4B-5、DEV仕様書 v2.3 §11〜§13）を突き合わせ、Long さんの回答で決まった内容。仕様書への反映は未実施。

## 決定事項

| No | 論点 | 決定 | 仕様書で直す箇所 |
|---|---|---|---|
| 1 | ログイン方式 | **ログインID＋パスワード**。パスワード再設定は**4桁の認証コード入力**（Figmaが正） | 統合 §12-2・サイクル §4B-5「メールアドレスとパスワード／メールリンク方式」を修正 |
| 2 | 納品先カードの表示 | 受取時間帯（複数は全部）と納品条件を表示（仕様が正。Figmaに追加） | デザイン側の修正 |
| 3 | 配送中のトラブル報告 | 配送中もトラブル報告できる。**不足（一部未受取／一部未配送／検品差異）は自動でトラブルとして記録**し運営へ | 統合 §12-2・§13-1 に「不足時の自動記録」を追記（app_reason_raw の値を決める） |
| 4 | 賞味期限 | **拠点ごとの期限追跡は不要。**期限切れはドライバーが現場で見て廃棄。**`delivery_lines.expiry_date` を仕様から外し、入力欄も作らない。**必要ならフェーズ3以降で起こす（その場合は THOMAS 出荷実績にロット／期限を載せて取込む案） | DEV §13.5・§14.7・§12.5（客向けAPIの除外項目）、統合 §13-1B、サイクル §7 DDL |
| 5 | 駐車報告 | **必要**（レシート画像＋駐車料金）。仕様漏れ | DEV §13.6「駐車料金は表示しない」との整合を確認し、項目・データモデルを追加 |
| 6 | 配送一覧の検索・絞り込み | 送り状番号・倉庫名での検索、ステータス絞り込みあり（仕様どおり） | なし |
| 7 | トラブル報告の宛先 | 基本的に運営宛て | なし（確認のみ） |
| 8 | COOL便のボタン名 | 「一部未配送のまま完了」（仕様どおり） | なし |
| 9 | STEP5 集金 | 任意。集金予定額0円なら項目を出さない（仕様どおり） | なし |
| 10 | 完了後の修正 | **完了から7日まで**各ステップを修正できる | 統合 §12-2「完了後も各ステップの内容を編集できる」に期限7日を追記 |

## 仕様にあり、Figmaに無かったため追加した画面（プロトタイプ反映済み）

- 中継先での荷物受取（営業所名・住所・営業所コード・電話）
- 同日・同地点での再受取
- 廃棄登録／棚卸し（差異は運営管理者へ通知）
- 到着予定時間帯の共有
- 未送信 N件の表示と再送（オフライン保持）
- マニュアル一覧・詳細
