## 1. どんなときに使うか

- 仕入れた商品に不良が見つかった（ロットの不良、または商品そのものの問題で全ロット）。
- 入荷で商品が足りず、運営が「代替品で対応」を選んだ（`55_発注・仕入・入荷/発注・仕入・入荷.md` §8-4）。
- 運営が、メニュー管理の「代替品設定」から設定する。下書き保存はなく、条件 → 対応方法 → 対象の確認のあと「確定する」で確定する（確定したら取り消せない。2026-10-06 hong）。

## 2. 対応は3つだけ

不良が分かった日（発覚日）と、便の出荷日で分かれる。入荷の形（月2回／毎日入荷の生鮮）では変えない。

| 対応 | 対象の便 | すること | 請求 |
|---|---|---|---|
| **① 差し替え** | 出荷日が発覚日より後（**出荷日の前日まで**に設定） | 不良の商品を代替の商品に替える（**1商品につき1商品**） | **元の商品の単価**で請求 |
| **② 補償** | 出荷日が発覚日以前（すでに納品した） | 代替の商品を届ける | **請求しない**（実績精算に0円の行で残す） |
| **③ 除外のみ** | ① と同じ | 不良の商品を外すだけ。お客様へ「納品分に含まれません」と知らせる | **請求しない** |

- この3つは ES で決めた（お客様への確認はしない）。
- 契約が終わったお客様には送らない（REQ-ALT-603）。

## 3. 設定で決めること

| # | 項目 | 決まり | 根拠 |
|---|---|---|---|
| 3-1 | 対象の範囲 | **対象期間（開始日〜終了日の発送分）**と**ロット**（ロット単位／全ロット）で指定する。生鮮でも全ロットになりうる | REQ-ALT-606・401・402 |
| 3-2 | 代替の商品 | 同じ温度帯・拠点のコースで出せる・同じ倉庫の商品を**提案するだけ**。運営は**提案の外の商品も選べる（警告つき）**。自販機の拠点で自販機に入らない商品も**警告だけ** | 台帳 J・M-2「代替品（追加の決まり）」 |
| 3-3 | 代替の商品の在庫 | 保存の前に、倉庫在庫（見込み）で足りるかを出す。足りない分は**追加発注**で入荷してから届ける | 台帳 J |
| 3-4 | 補償の数 | 「注文した数を全部」か「残っている分だけ（理論在庫）」を、**運営が不良ごとに選ぶ**。初期値は「注文した数を全部」 | 台帳 J |
| 3-5 | 補償を届ける便 | **次の便が初期値**。対象の注文の一覧で、便ごとに「次の便／その次の便／追加配送」に変えられる。次の便がない・遠い（目安14日より先）ときは追加配送。**追加配送の配送費は ES の負担** | 台帳 J |
| 3-6 | 倉庫の不良の在庫 | 「仕入先へ返品／倉庫で廃棄」を選ぶ。どちらも**出荷を止める** | 台帳 J |
| 3-7 | お客様への知らせ | **既定で送る**（運営が外せる）。メール X17＋法人Web のお知らせ。該当の商品を注文した拠点だけ | 台帳 J |

## 4. 保存すると直るもの（下流）

| 直る先 | 中身 | 根拠 |
|---|---|---|
| 注文・配送データ | 明細を同時に直す。明細に**代替元**を残す（配送トラブルの代替品と同じ記録） | REQ-ALT-701 |
| 出荷指示 | 送ったあとなら、出荷日の前日まで**版を上げて再送**。出荷日からは ② 補償 | REQ-ALT-702 |
| 発注 | 代替の商品の必要数を足し、不良の商品を減らす。本発注の後なら**追加発注**。発注の画面に「代替品数」 | REQ-ALT-706 |
| 拠点の在庫 | 拠点に残った不良品は**廃棄として記録**し、理論在庫から引く（管理ロスにしない）。ES配送便＝ドライバーが次の便で回収・廃棄、COOL便＝法人が廃棄して棚卸報告で申告 | REQ-ALT-705 |
| 請求 | §2 の表のとおり。差し替えの分の税は 8% の行に分ける | REQ-ALT-704、課題一覧 4a-8（2026/10/03） |
| お客様の画面 | お届け詳細・納品書・月次注文に「代替品（元：〇〇）」 | REQ-ALT-708 |
| 配送の現場 | ドライバーアプリ・委託配送先の納品リストに「代替品（元：〇〇）」と回収・廃棄の指示 | REQ-ALT-709 |

- 保存のとき、上の「下流への反映」を一覧で見せる。
