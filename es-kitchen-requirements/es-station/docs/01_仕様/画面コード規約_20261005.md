# 画面コード（Screen Code）の規約（2026-10-05・hong 回答）

画面設計書・要件（Spec/REQ）・Figma の画面・チケットで同じ画面を指すための ID。画面設計書 Q7 の回答（2026-10-05）を正として写した。

## 1. 形

`<Module(2)>_<Feature(4)>_<Seq(3)>`　例：`UA_PAYM_003`

| 部分 | 内容 |
|---|---|
| Module（2文字） | サイト・アプリ。下の表 |
| Feature（4文字） | 機能（英大文字 4 文字）。例：PAYM＝Payment、PLAN＝プランマスタ |
| Seq（3桁） | その機能の中の画面の番号（001〜）。**状態（タブ・モーダル・エラー）の番号ではない** |

| Module | 対象 |
|---|---|
| UA | User App（個人アプリ） |
| DA | Driver App（ドライバー） |
| CW | Company Web（法人Web） |
| AW | Admin Web（運営管理者Web） |
| SW | Supplier Web（仕入先サイト） |
| OW | Outsource Web（委託配送先Web） |

## 2. 決まり（必須）

- プロジェクトの中で一意（重複しない）
- 画面が増えたら番号を**増やすだけ**。既存の画面のコードは変えない
- コードを変えるのは、画面の本質が変わったときだけ（分割・統合・フローの変更・対象の変更）

## 3. 運用

- 画面コードを Spec/REQ・Figma の画面・チケットなど、対応する資料すべてに付ける
- 画面を分けたがコードがまだ無いときは、タスクの担当が上の決まりで自分で決めて PM に知らせるか、PM に知らせて後から付けてもらう

## 4. 画面設計書での使い方

- データ（`docs/05_画面設計書/データ/*.py`）の `SCREENS[].code` に書く。状態（`VIEWS`）の id は別に 001〜 を振る
- 例：プランマスタ（運営管理者Web）＝ `AW_PLAN_001` 一覧／`AW_PLAN_002` 詳細／`AW_PLAN_003` 登録・編集
