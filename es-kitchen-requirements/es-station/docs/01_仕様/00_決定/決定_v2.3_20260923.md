## 決定にともなう変更

### ① 機種IDの体系が変わります（⑫-3 B）

```
変更前　^(RF|VM|MW|HW|BX)[0-9]{6,}$
変更後　^(RF|FZ|VM|MW|HW|BX)[0-9]{6,}$
```

| 機種区分 | 接頭辞 | 意味 |
|---|---|---|
| 冷蔵庫 | **RF** | 冷蔵ショーケース |
| 冷凍庫 | **FZ** | 冷凍ストッカー（**新設**） |
| 自動販売機 | VM | |
| 電子レンジ | MW | |
| ホットウォーマー | HW | |
| 資材ボックス | BX | |

既存の冷凍機種を振り直します。

| 変更前 | 変更後 | 名称 |
|---|---|---|
| RF000005 | **FZ000001** | 冷凍ストッカー 60L |
| RF000006 | **FZ000002** | 冷凍ストッカー 100L |
| RF000007 | **FZ000003** | 冷凍ストッカー 150L |

> **移行の注意**　すでに RF000005〜7 で登録された貸出・契約・納品実績があれば、
> ID の付け替えが要ります。**Phase2 の開発が始まる前に決まったので、いまなら移行データはありません。**

### ② 機種マスタ（⑫ B・⑫-2・2 B）

**（2026/09/25 訂正）新しい項目は足しません。** 当初この欄に「無料対象プラン」という新項目を書きましたが、
機種マスタには **P1 から「初期・月額無料対象プラン」** という欄がすでにあり、これがそのまま使えます。

| 既存の項目 | 内容 |
|---|---|
| `model.free_threshold_lite`（ライト_無料判定_月次提供数） | コース＝ESライトの契約で、月次提供上限の合計がこの値以上なら初期料金・月額料金を無料にする。**空欄＝そのコースでは無料にしない** |
| `model.free_threshold_std`（スタンダード_無料判定_月次提供数） | 同じくスタンダードのとき |

コース別に分かれているので、**ライトの冷凍庫を空欄にすれば「ライトでは冷凍庫は無料にならない」**が表せます。
しきい値は `ES食数 × 納品回数4`（プラン50＝200／100＝400／150＝600）。

| 機種 | 月額 | ライト | スタンダード |
|---|---|---|---|
| RF000001 冷蔵46L | ¥4,000 | 200 | 200 |
| RF000002 冷蔵84L | ¥6,000 | 400 | 400 |
| RF000003 冷蔵120L | ¥8,000 | 600 | 600 |
| FZ000001 冷凍60L | ¥4,500 | （空欄） | 200 |
| FZ000002 冷凍100L | ¥5,500 | （空欄） | 400 |
| FZ000003 冷凍150L | ¥7,000 | （空欄） | 600 |
| BX000001 資材ボックス | ¥0 | 200 | 200 |

```
サイズ差額 ＝ 選んだ機種の月額
             −（その契約で無料になる同じ区分の機種のうち、いちばん月額が高いもの）
             ※ マイナスなら ¥0
```

**足す・変える項目**

| 項目 | 内容 | 必須 |
|---|---|---|
| **最大収納数** | 容量判定に使う数（既存項目の必須条件を変える） | **冷蔵庫・冷凍庫・自動販売機・資材ボックスは必須**／電子レンジ・ホットウォーマーは持たない |
| **解約時の回収額** | 既存項目。**ここが標準額**。契約側で上書きできる | 任意（別途見積の機種は契約で必ず入れる） |
| ~~料金バージョン（改定履歴）~~ | **（2026/09/25 決定）機種マスタは料金バージョンを持ちません。**現行画面にもなく運用でも使っていないため、フェーズ2でも足しません。料金を変えるときは初期料金・月額料金・解約時の回収額を直接直します（子契約の①費目行は生成時に金額を固めるので、あとから変わりません）。プランマスタ・オプションマスタは引き続きバージョンを持ちます | — |

### ③ プランマスタに足す項目（⑫-5 C）

| 項目 | 内容 |
|---|---|
| **冷凍の割合** | 冷凍庫の容量判定に使う。`冷凍の必要収納数 ＝ ES食数 × 冷凍の割合`。**既定 30%**（2026/09/29 追補 28-155 で廃止。2026/09/30：冷凍は割合ではなくプランでの個数で決める〔要件シート 行170・2026/09/30 hong〕） |

**既定値が30%な理由**　子契約の「月次提供数上限（冷凍・冷蔵）」の説明に
**「冷凍はプラン全体の30%が上限」**（議事録 2026/09/15）とすでに書いてあります。これを項目にします。

例：プラン100・冷凍の割合30% → 冷凍の必要収納数 30 → 最大収納数が 30 以上の冷凍庫だけ選べる

**冷蔵庫は ES食数そのまま**（⑬）。プラン100 なら最大収納数 100 以上の冷蔵庫だけ選べます。

### ④ 契約に足す項目（2 B）

| 項目 | 内容 |
|---|---|
| **解約時の回収額（上書き）** | 空なら機種マスタの標準額を使う。自販機のように契約ごとに違う場合だけ入れる |

### ⑤ 設備の異動に「移設」は作りません（3）

拠点の住所が変わっても、**設備の異動レコードは作りません。**お客様の責任で移動していただきます。

| | |
|---|---|
| 貸出ID | **変わらない** |
| 最低利用期間 | **変わらない**（起算し直しにならない） |
| 費用 | **無料**（お客様が運ぶため） |
| 運営が運ぶ場合 | **有料オプション**として都度見積で足す（7 と同じ扱い） |

> 運営が運ばない代わりに、法人サイトの申込画面に
> 「**設備の移動はお客様にてお願いします。運営での移動をご希望の場合は別途お見積りします**」と出します。

### ⑥ 承認は拠点単位になります（1 B）

| | |
|---|---|
| 申請 | 1申請に複数の拠点が入る（法人サイトは変えない） |
| 承認 | **拠点ごとに承認・却下する。**拠点ごとに承認ステータスを持つ |
| 申請のステータス | 全拠点が承認済み＝承認済み／一部だけ＝**一部承認**／全部却下＝却下 |
| データ構造 | 申請テーブル ＋ **申請明細（拠点）テーブル**（承認ステータス・承認日時・承認者を持つ） |
| お客様への通知 | **拠点ごとに送る**（1拠点の承認を待って全部止めない） |

### ⑦ お支払い方法の切替（6 C）

| | |
|---|---|
| 承認と同時 | 契約の支払方法を **口座振替** に切り替える |
| 手続きが終わるまで | 請求書には **お振込** と印字し、振込先を載せる |
| 手続きが終わったら | 次の請求書から口座振替の記載になる |
| 持つ項目 | 契約に「**口座振替の手続きステータス**（未手続き／手続き中／完了）」 |

> 請求は止めません。手続き待ちの間も**お振込で請求できる**ので、売上の計上が遅れません。

### ⑧ 休止の記録（8-2 A）

**選んだ理由だけ**を残します。「どの提案を見て、選ばなかったか」は記録しません。
承認画面には「休止の理由：オフィスの改装・移転」と、任意の自由記述だけを出します。

### ⑨ 設備の縛りが契約満了を越えるときの明示（4 A）

親契約の満了日は動かしません。代わりに、**法人サイトの申込画面と運営の承認画面の両方**に出します。

> この設備は **2028/02/09** まで最低利用期間があります（ご契約の満了日 2027/09/30 より後になります）。
> この日より前に解約される場合、この設備ぶんの違約金がかかります。
