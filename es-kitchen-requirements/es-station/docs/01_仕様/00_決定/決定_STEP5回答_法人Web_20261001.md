## 2. 決定から決まる細かいこと（反映のときの前提。違えば指摘してください）

### Q1 横浜営業所
- 横浜営業所：ESスタンダード 100プラン（ES000004）・COOL便・冷蔵2回／冷凍2回・月次提供数 冷凍 1〜20・冷蔵・常温 0〜80（今の本社の注文画面の中身を横浜へ移す形）。
- 自販機の見本は本社（ESライト（自販機）100・ES配送便・冷蔵のみ）。自販機の枠の表示（ダブル枠・シングル枠・最大格納数）は本社へ移す。
- 運営の商品注文管理・資材注文管理の横浜営業所の行もコース・自販機の列を直す（ライト（自販機）・あり → スタンダード・なし）。本社は逆。
- 横浜営業所の請求・貸出（冷蔵庫・冷凍庫）・子契約を足すかは反映のときに範囲を決める（最低限：拠点管理の一覧・詳細、ホーム、在庫点検、運営の法人・拠点・契約の一覧）。

### Q2 資材注文
- 法人Webの資材注文は「受付期間は商品と同じ・1回でお届け」をやめ、**いつでも注文できる**形にする。注文ごとに資材便（ヤマト）の配送データを作り、ホームのカレンダーに出す。
- **月1回まで**は料金に含む。その月の2回目以降の注文・配送は**別料金**。数え方は「資材便の配送の回数（サイクル月ごと）」。
- 別料金はオプションとして子契約に付ける。**OP000036「資材の追加配送（単発・1回）」を新設**（§2-2。金額は未定）。
- 法人Webの注文画面に「今月の資材注文は1回目（料金に含む）／2回目以降は別料金 ¥…」を出す。
- 初期セット（申込の承認で自動オーダー）は数に入れないか【要確認】。

### Q3 休止中の在庫点検
- 休止中の拠点の状態は「点検なし」ではなく「**任意**（休止中）」。申告すれば記録し、運営の実績精算に使う。申告しなくても「未申告（期限切れ）」にしない。
- 運営側：休止中の実績精算の結果は、再開時か解約時の請求書にまとめる（P5。結果の持ち場所は STEP3 の反映で設計）。
- 名古屋営業所は 2026年10月サイクルから休止なので、7〜9月度は「申告済」に直す。

### Q4 レビュー
- 法人Webの列：レビューID・投稿日時・拠点・商品と星・評価タグ。「コメント」列を外す。
- 見える範囲は 決定 #55 と同じ：法人アカウント＝自社の全拠点、拠点アカウント＝自分の拠点だけ。
- 運営の「レビュー・ご意見」はこれまでどおり（ご意見も見る）。

### Q5 納品書
- 法人Webで対象月・拠点を選んで出力する（形式は今の納品書と同じ。2026/09/30 要件シート追記「OK」）。
- その月の納品が始まっていれば出せる（例：8月時点で9月の納品が始まっていれば9月分）。
- 置き場所（ホーム／月次注文の注文履歴／拠点管理）は反映のときに提案する。

### 在庫点検をしなかった拠点（2026/10/01 夜 回答）
- **請求は保留しない**（事務手数料がかかり、請求しないことはできない）。点検しなかった拠点にも通常どおり請求し、**未点検ペナルティ（¥3,000・2026/08/25 決定）** を付ける。
- 判定は **20日（お客様の締め）時点で未申告** と解釈【要確認】。21日以降に運営が手で入れた数は実績精算（管理ロス）に使い、ペナルティはそのまま。
- 法人Web 拠点管理 画面仕様 2-5「期限を過ぎたとき：請求が保留になり事務手数料」は、反映のときに「請求は保留しない・未点検ペナルティ」に直す。

### 1商品あたりの上限（§2-4 Q4・§2-5 仮置き値の見直し）
- 出どころは **Order-Spec（2026/07/31）§5 の例「5個／商品」だけ**。一方、2026/01/27 の会議で **「最大注文数は不要」で確定**（要件定義まとめ 議題・RD-MN 系）。お客様の要件ではない。
- → **決定（2026/10/01 夜 Long さん）：B「最大注文数は不要」（1/27 の決定どおり）**。1商品あたりの上限は**持たない**（プランマスタにも作らない）。§2-4 Q4（プランマスタに持つ）と §2-5 の仮置き値（50プラン 5個）は**取り消し**。按分・AI の制約からも外す。**Order-Spec（§5「Max mỗi sản phẩm」・§8.6）から外すよう AI チームに伝える**。

### 提案 → 回答（2026/10/01 夜）：納品書＝**A**、要件シート 行130・172・185＝**提案どおり（各 A）**
- **納品書の置き場所**：A 月次注文 ＞ 注文履歴の行（拠点×対象月）に「納品書」ボタン（推奨：決定の「月・拠点ごと」と一覧の単位が同じ）／B 拠点管理の拠点詳細に「納品書」タブ／C ホームのお届け詳細（便ごと）
- **要件シート 行130**（運営の注文確認で、法人が入れたか ES が直したかが分からない）：A 商品注文管理の一覧・詳細に「法人の登録（日時・担当者）」「ES の変更（日時・担当者）」の2列を出す（推奨。変更履歴は既にある）／B 今のステータス1つ＋最終更新のまま
- **要件シート 行172**（冷凍は毎月の変化が少ないので、メニュー表を冷蔵と冷凍で分けたい）：A 月間メニューに「メニューPDF（冷蔵・常温）」「メニューPDF（冷凍）」の2欄。冷凍の商品があるメニューは2つそろわないと公開できない。法人Webはスタンダードの拠点に2つ、ライトの拠点に1つ出す（推奨）／B PDF は1つのまま
- **要件シート 行185**（注文画面で冷蔵・常温・冷凍を文字のタグでなく絵で見せたい）：A アイコン＋短い文字（色も分ける：冷凍・冷蔵・常温）。文字を残すのは色やアイコンだけでは分かりにくい人のため（推奨）／B アイコンだけ／C 今の文字のタグのまま

### 仮置きの値（§2-5）の扱い
- 1商品の上限・資材の追加配送の金額・冷凍の配送回数・平均単価の目標は、決定にも資料にも数字が無いため、デモが動くように Claude が仮の値を置いた。**この仮の値を「提案値」としてお客様に確認する**（根拠は §2-5 の表）。確認できるまではデモ・仕様とも仮置きと明記する。

## 2-7. 追補：自販機の運営の標準数（2026/10/01 夜 Long さん回答・v1.59b で反映）

|---|---|
| 持ち方 | 法人Webの注文画面と同じ**枠（ダブル・シングル・ベルト）ごと**に作る |

| 機種 | **機種ごと**に作る。いま自販機は2種類（富士電機・サンデン）。機種マスタに VM000002（サンデン）を仮で追加。列の構成（格納数×列数）は仮：富士電機＝ダブル10×5・ダブル8×6・シングル10×6・ベルト5×8、サンデン＝ダブル10×4・シングル8×8・ベルトなし |
| 入らない商品 | 自販機に入らない商品（機種の列の格納数に合わない・要件 行141）と対象外の商品は入れない |

- お客様に確認：機種ごとの実際の列の構成、自販機の平均仕入単価の目標、サンデンの機種コード・名前。
