# 決定：STEP3 追補 請求ルール（2026/10/01）

> 依頼者：Long（Tran Duc Long）／作成：Claude（Cowork）。STEP3 の請求まわりの見直し（資料どうしの矛盾 A1〜A7・ルールが無いもの B1〜B13・画面に無いもの）のうち、P1〜P9 への回答。
> 突き合わせた資料：要件定義まとめ（RD-BL-001〜104）、要件シート Phase2 の経理の行（112〜154・186・188）、決定（28-1a・28-72・STEP2 Q4 ほか）、請求デモ。
> **この資料は決定の記録だけ。デモ・仕様書（要件定義まとめを含む）はまだ変えていない。** 反映前の版は `02_デモ/履歴/` に残す。

## 1. 決定

| # | 論点 | 決定 | 内容 |
|---|---|---|---|
| P2 | 前払い済みの月に休止・解約・プランダウンが入ったとき（B2） | **A** | すでに請求した月の分は、次の請求書で相殺する（調整のマイナス行）。相殺しきれない分はシステムの外で返金する（RD-BL-073・074 と同じ考え方）。リードタイム2〜3ヶ月・年払いにも同じルールを使う |
| P3 | 初回の請求（B3） | **A** | 申込の承認が25日の確定より後になり、初回分を載せる請求書が間に合わないときは、次の（初回の）請求書に2ヶ月分をまとめて載せる |
| P4 | 送付後の請求書の訂正（B9） | **A** | 原則は翌月の請求書で相殺する。請求書の差し替え（Bill One でキャンセル→別のIDで再発行。RD-BL-023）は、運営が判断したときだけ。お客様ごとの希望（要件シート 行188）は持たない |
| P5 | 休止中の実績精算（A3） | **B** | 休止中も、必要であれば月ごとの実績精算（在庫点検・計算）は行う。ただし請求はせず、**再開時か解約時にまとめて請求する**。RD-BL-075「休止中も実績精算があれば請求」を訂正。休止中は子契約を作らない（28-1a）ため、休止中の実績精算の結果をどこに持つかは反映時に設計する |
| P6 | ES-QR の請求時期（A2） | **A＋** | ES-QR の月額は**前払い**（ほかの月額と同じ）にそろえ、RD-BL-003（後払い）を訂正する。**前払いに間に合わない場合**（請求の確定後に ES-QR を使い始めた など）は、**次の請求書に繰り越して請求できる**ように調整できること |
| P7 | 実績精算の期間（A4） | **A** | 21日〜20日で固定する。RD-BL-078「各社の棚卸日で区切る（21日は目安）」を訂正 |
| P8 | お試し期間中の実績精算（B8） | **A** | 請求する。お試しキャンペーン割引（DC000013）が相殺するのは固定額（プラン料金）だけで、実績精算（管理ロス）は請求する |
| P9 | 消費税の計算（B10） | **A** | ES で消費税を計算し（四捨五入・請求書ごと・税率ごと。v1.43）、税額も Bill One に送る。画面と請求書の金額が必ず一致するようにする |
| P1 | 日割り（B1） | **日割りしない** | 契約はサイクル単位にする。月額（プラン・設備・オプション）は、使った日数で按分せず、サイクル月ごとに満額で請求する。設備・オプションの追加・撤去・プラン変更も、適用はサイクル月の単位（どのサイクル月から効くかを決めて登録する） |
