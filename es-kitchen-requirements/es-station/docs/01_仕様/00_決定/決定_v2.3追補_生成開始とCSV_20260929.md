## 52. 予定・配送データ・子契約を作り始めるのは、拠点を確定（本登録）したとき

| 状態 | 予定（`shipping_plans`） | 配送データ（`deliveries`） | 子契約（`contract_months`） |
|---|---|---|---|
| 仮登録（受付の「設定中」） | **作らない** | **作らない** | **作らない** |
| 拠点を確定（本登録）した | 開始サイクル月から設定期間の末まで**すぐ作る** | 開始サイクルの**オーダー開始日を過ぎていれば、すぐ作る**（過ぎていなければ通常どおりオーダー開始日に） | 開始サイクル月の分を**すぐ作る**（生成基準日を過ぎた分） |
| 休止中／お試し満了から本導入までの空白（28-35）／終了 | 作らない | 作らない | 作らない |

- 理由：仮登録の間は配送ルート（倉庫・配送会社・リードタイム・納品サイクル）が未入力か途中で変わる（28-77）。作ってから消すと、法人カレンダー・委託配送会社Web・件数しきい値に一時的な予定が出てしまう。
- **確定は拠点単位**（申請詳細 15.1 #15）。同じ申請の中でも、確定した拠点の契約から順に作る。
- 確定がその開始サイクルの**オーダー締切を過ぎたとき**は、28-27 のとおり**開始サイクル月を自動で翌サイクルへ直してから**作る。
- 確定のバッチ処理は日次バッチを待たず、確定の操作の直後に**その契約だけ**を対象に `contract_monthly_generate` → `plan_rollout` → `delivery_materialize` の順で走らせる（日次バッチでも拾えるよう、処理は冪等のまま）。
- 変更系（プラン変更・再開など）は既存のルールのまま（適用月以降の予定を作り直す・休止の承認で予定を消す）。再開の確定（再開サイクルから「本登録」に戻る・28-65）で、再開サイクルから予定を作る。
- デモ：契約配送設定に「予定・配送データの生成：2026/09/10 拠点を確定（本登録）→ 10月サイクルから作成（仮登録の間は作らない）」を表示。

## 53. THOMAS の CSV を画面から出力・取り込む

「出荷指示・取込」画面にボタンを置く。

| ボタン | 何をするか |
|---|---|
| **出荷指示CSVを出力（THOMAS）** | 倉庫と対象（2週間の窓・追加分）を選んで、その時点の出荷指示（DEV §19.1 の項目）を CSV で出す。**確認用・手動連携用**。出力しても**送信にはならず、`locked` にもしない**（`locked` は送信成功だけ・決定v2.1 #3） |
| 送信履歴の行の **CSV** | その版で**送った内容そのもの**（`ship_orders.export_file_ref`）をもう一度ダウンロードする |
| **送り状用CSVを出力（ヤマト）** | 追補4 #46 の暫定項目（営業所止めの宛名＝受け取る委託配送会社・記事欄・お届け予定日＝営業所に着く日・箱）で出す |
| **出荷実績CSVを取り込む（THOMAS）** | DEV §19.4 の処理。ファイル単位の `import_id`・行ごとの処理・エラー行は要確認 `import_error` |
| **送り状番号CSVを取り込む** | DEV §19.3 の処理（同上） |
| **ひな形（出荷実績）／ひな形（送り状番号）** | 取り込み用の見本ファイル（見出し行＋例の行）を出す |
| 取込履歴の行の **エラー行** | 取り込めなかった行（行番号・配送No・理由）を CSV で出す |

- 文字コードは **Shift_JIS**（出力層で変換・#45）、列の順序・名前は THOMAS から届くまで暫定。デモの出力は見本（UTF-8・BOM付き）。
- 出力・取込の操作は**運営（物流）だけ**。出力も監査ログに残す（誰が・いつ・どの窓）。
