# 決定：法人Web 法人アカウント／拠点アカウントの決まっていないこと H1〜H5（2026/10/01）

> 依頼者：Long（Tran Duc Long）／作成：Claude（Cowork）。`基本設計_全体の定義_提案_20261001.md` §10-7-5 の H1〜H5 への回答。

## 1. 決定

| # | 論点 | 決定 | 内容 |
|---|---|---|---|
| H1 | 法人アカウントのホーム（全拠点を見るホーム）の中身 | **スケジュール＋お知らせ一覧** | 委託配送会社のポータルと同じ考え方で、全拠点のお届けのスケジュールと、お知らせの一覧を出す。拠点で絞り込める（Claude の案の範囲） |
| H2 | 法人アカウントが出した申請を、拠点アカウントが取り下げられるか | **できない** | 取り下げられるのは、申請を出したアカウントと法人アカウントだけ |
| H3 | 拠点アカウントが「拠点を追加」した新しい拠点を、追加したアカウントから見られるか | **A：見えない** | 新しい拠点と、その「拠点を追加」の申請は、追加したアカウントの拠点一覧・申請一覧に出さない。新しい拠点の拠点アカウントと法人アカウントで見る。結果（承認・却下の理由）はメールで申込者に届く（2026/10/01 Long さん回答 A） |
| H4 | 拠点アカウントの申請一覧は自分の拠点だけか | **はい** | 拠点アカウントの申請一覧は、自分の拠点の申請だけ（H3＝A なので例外は足さない） |
| H5 | 機種コード（RF000002 など）を法人Webに出すか | **出す** | 管理・問い合わせのときに機種を特定できるように、機種名と一緒に機種コードを出す（Claude の案「出さない」は採らない） |

## 2. H3 の選択肢（A に決定）

前提：拠点アカウントは拠点ごとに1つ（C1）、見える範囲は「その拠点だけ」（C3）。新しい拠点には新しい拠点アカウントが発行され、ログイン案内はその拠点のご担当者へ送る（28-145）。H4（申請一覧は自分の拠点だけ）をそのまま当てはめると、追加した人は「拠点を追加」の申請の状況（承認・却下の理由）も見られなくなる。

| 選択肢 | 内容 | メリット | デメリット |
|---|---|---|---|
| A | 見えない（新しい拠点は、新しい拠点アカウントと法人アカウントで見る） | 「拠点アカウント＝その拠点だけ」の決まりのまま。権限が単純 | 追加した人が申請の結果（承認・却下・却下理由）を確かめられない |
| B | 見える（追加したアカウントにも新しい拠点の権限を付ける） | 追加した人がそのまま管理できる | 1つの拠点アカウントが複数の拠点を見ることになり、決まり C3 が崩れる。権限の仕組みが複雑になる |
| **C（推奨）** | 拠点は見えないが、自分が出した「拠点を追加」の申請だけは申請一覧で見える（受付〜承認・却下まで）。承認後は、新しい拠点アカウントと法人アカウントで見る | 決まり C3 を守りつつ、出した人が結果を確かめられる。却下理由も伝わる | H4 に「自分が出した拠点を追加の申請は例外」と1行足す必要がある |
