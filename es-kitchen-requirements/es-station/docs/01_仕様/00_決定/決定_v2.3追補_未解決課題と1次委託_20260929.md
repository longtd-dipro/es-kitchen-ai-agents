## A. 運営の決め事

### 34. 委託配送会社の専用サイトに出す範囲（A-1・統合 §18 No.1 解消）

- **確定（オーダー締切後）の配送データ**：全項目（拠点名・住所・納品日・温度帯・数量・納品条件・送り状）。
- **予定（締切前）**：**翌月サイクルまで**。**納品日・拠点名・温度帯・件数だけ**（数量は出さない）。「予定」の印を付ける。
- 見えるのは**自社が担当する区間（レグ）がある配送だけ**（#51）。
- 画面は運営の「スケジュール 月・週・日」を委託配送会社Web（テーマ carrier）に流用する。

### 35. 短消費期限の商品の自動通知（A-2・統合 §18 No.6 解消）

- **出荷日から納品日までの日数 ＞ 商品の消費期限日数（`products.shelf_life_days`）− 安全日数** の商品を含む配送を、要確認 **`shelf_life_warning`** に出す。
- 安全日数は**全社共通の設定1つ**（`shelf_life_safety_days`・既定 **2日**）。
- 判定するとき：予定の生成・再計算（振替でリードタイムが伸びたとき）、倉庫の変更、複製。
- 分割するかどうかは従来どおり**運営が判断**する（自動で分割しない）。

### 36. 資材の配送データを作るタイミング（A-3・統合 §20 #22・#35 解消）

- **資材のカートを確定したたびに**配送データを作る。
- **同じ拠点・同じ納品日・まだ出荷指示を送っていない資材の配送データがあれば、そこに明細を足して1件にまとめる**（新しく作らない）。
- 出荷指示は既存の日次の拾い上げ（catch-up）で送る。

### 37. 法人の変更申請が「申請中」のままのとき（A-4・統合 §20 #19 解消）

- **処理期限＝その配送のオーダー締切。**
- **締切の3日前**に要確認 **`change_request_due`** に出す（日数は設定 `change_request_warn_days`・既定 3日）。
- 締切を過ぎても未処理なら、**運営が処理するまで要確認に残す**。**システムは自動で却下しない**（従来どおり）。

### 38. 都度配送（資材）のリードタイムの意味（A-5・統合 §20 #18 解消）

- ほかの配送パターンと同じく **出荷日＝納品日−リードタイム**。
- 資材の納品日は **「注文日の翌日以降で、リードタイムを守れる最初の納品可能日」**（配送祝日・納品不可曜日・受取不可日・出荷不可日の判定は通常と同じ。資材はサイクルの外なのでサイクル休止は判定しない）。

### 39. 代替品の記録（A-6）

- `delivery_lines` に **`substituted_from_product_id`（代替元の商品）** を足す。1行＝実際に渡した商品。
- **請求は代替元の商品の単価**で計算する（「元の商品の料金で請求」の決定を実装できるようにする）。
- 登録するのは、トラブルの解決で「代替品で全量納品」を選んだときと、実績の修正のとき（運営のみ・理由必須）。

### 40. 中止したときの運賃（A-7）

- 再配達の「運賃を請求する／しない」フラグを**中止にも使う**。列名を **`freight_billable`**（理由は `freight_bill_reason`）に改める（旧 `redelivery_billable`）。既定は「しない」、「する」にするときは理由必須。
- 商品は請求しない（従来どおり）。廃棄は `delivery_lines.disposed_qty`、残った商品の返送は #41。

### 41. 残った商品を本社へ返送する（A-8）

- 複製の理由に **「返送」（`duplicate_type = return`）** を足す。返送のときだけ、**納品先を返送先に替えられる**。
- 返送先は**倉庫マスタに `warehouse_type = return`（返送先）として登録**した拠点（本社など）から選ぶ。`deliveries.return_to_warehouse_id` に持ち、住所スナップショットは返送先の住所にする。
- 数量は残数。**請求の対象外**。親子1階層・枝番のルールは複製と同じ。

### 42. 法人Webの表示名（A-9）

状態とは別に、**法人Web用の表示名**を持つ（運営Webの状態名は変えない）。

| 運営側の状態・状況 | 法人Webの表示 |
|---|---|
| 取消（代わりの便あり） | 配送日調整中 |
| 未解決のトラブル報告あり（状態は 出荷済 など） | 状態はそのまま＋「配送状況を確認中です」の注記 |
| 子（確認中） | 再配送準備中 |
| 一部納品済 | 一部お届け済み |
| 再配達待 | 再配送予定 |
| 取消（代わりの便なし）・中止 | お届け中止 |

- 〔上書き〕統合 §13-2 ①「法人へは『確認中』として表示」を「配送日調整中」に置き換える。

### 43. ドライバー未設定の要確認（A-10）

- 要確認 `assignment_missing` は **「納品日の前日」になっても、割り当てる区間（#48）に担当者が無いもの**の1本にそろえる。
- 〔上書き〕DEV §13.1「lock 時点で未割当なら要確認」、統合 §8-5「納品日の1週間前を切って未割当」を置き換える。それより前は月・週表示の「未割当 N件」バッジで見る。

### 44. 暫定6件（A-11）

- `HU` の意味・倉庫コード・祝日データの出どころ・ヤマト／トーマスの正式名・保冷バッグを回収しない件・問い合わせ電話番号は、**暫定値のまま実装を進める**。6件を1枚の確認表にして運営に送り、回答が来たら本文を差し替える。

## B. ベンダー確認が要るもの

### 45. トーマスの出荷指示（B-1）

- 取消は**再送方式（数量0の新しい版）で確定**。取消I/Fがあっても使わない。
- CSVは DEV §19.1 の最低限の項目で実装し、**出力の部分だけ差し替えられる作り**にする。列の順序・名前が届いたら出力部分だけ直す。
- UTF-8 に対応できなければ、**出力のときに Shift_JIS に変換**する。

### 46. ヤマトへ渡す項目（B-2・暫定）

- 営業所止めの宛名：**受け取りに行く委託配送会社**。記事欄に拠点名と配送No。
- お届け予定日：**営業所に着く日**（1次のリードタイムの参考値から出す）。
- トーマスのCSVに欄が無ければ、**送り状用のCSVを別に出す**。
- **ヤマトへの確認待ちの暫定**とする（統合 §18 No.19 は「暫定」に変える）。

## C. 1次区間が委託配送会社のとき（実際にある）

### 47. 引き取り便の送り状番号をESで採番する（D-1・決定 #55 の実装）

- `delivery_tracking_numbers.issued_by` に **`es_generated`** を足す。`box_no`・`box_total` を持つ。
- 番号は **配送No＋箱番号2桁**（例：`DL-261020-0021-01`）。
- **出荷指示の送信に成功した時点で、見込みの箱数ぶん作る**。出荷実績の箱数が違えば、足りない分を足し、余った分は `voided` にする。
- 追跡ページのリンクは出さない。

### 48. ドライバーを割り当てる区間（D-2）

- **運送会社（`parcel_carrier`）が運ぶ区間は割り当てない。自社（`self`）・委託（`partner_driver`）が運ぶ区間は割り当てる。** 1次・2次の区別ではなく、区間の運び手で決める。
- 〔上書き〕決定 #60「運用は当面 2次だけ割り当てる（1次は運送会社が運ぶ）」を置き換える。
- 委託の区間は、その委託配送会社も自社のドライバーを割り当てられる（従来どおり）。

### 49. 中継先での受け渡しの記録（D-3）

- **状態は増やさない**（中継の途中の状態を持たない決定は維持）。
- `delivery_legs` に **`picked_up_at`・`picked_up_by`**（区間ごとの受取時刻・受取者）を足す。
- **受取済になるのは、ESのアプリで最初に受け取ったとき**（1次が委託なら倉庫での受取）。2次のドライバーが中継先で「荷物受取」をしたら、その区間の受取時刻だけ入る（状態は受取済のまま）。
- 最終区間の受取が無いまま納品日の翌朝になったものは、既存の欠配検知（`delivery_detect_missing`）で拾う。

### 50. 契約配送設定で選べる配送会社・中継先（D-4）

- 1次・2次とも**配送会社マスタの全件**（運送会社・委託・自社）から選べる。
- 中継先は**倉庫マスタの中継（`HU`）全件**から選ぶ。委託配送会社の拠点も中継先として登録できる。

### 51. 委託配送会社Webで見える範囲（D-5）

- 委託配送会社は、**自社が担当する区間がある配送だけ**見える。
- 操作できるのは自社の区間だけ（1次担当は倉庫での受取まで、2次担当は中継先での受取から納品まで）。
