`_共通_メッセージ.py` で、SW の `S320`（再設定完了）・`S321`（申込受付）・`S322`（回答しました。）・`S323`（分納で回答しました。）と、DA の `S320`（未送信の再送）・`S321`〜`S323`（スキャン）が**同じ ID**で、後ろにある DA が上書きしていた（`dict.update`）。そのため SW のデータ（`SW_AUTH` 010・014、`SW_ORDR` の S322・S323）が DA の文言を指していた。**check では見つからない**（同じ ID は1つの行として扱われるため）。
→ DA 側を S403〜S19 へ移し、SW は S322・S323 が本来の文言に戻り、S320・S321 は共通の S401・S402 になった。

今後の予防：新しい ID を足す前に、`ast` などで **MESSAGES の同じキーが2回出ていないか**を確かめる（この gộp で使った方法）。並列実行計画 §2 の「帯」は DA の S・I・W が「310〜」と開いていて SW の「320〜」とぶつかる書き方だった。次に帯を決めるときは終わりの数も書く。
