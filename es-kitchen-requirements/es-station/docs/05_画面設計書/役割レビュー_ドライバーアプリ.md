## (b) QC テスト観点の種（機能ごと・入力 → 期待結果）

### DA_AUTH（ログイン・再設定・アカウント）
- ID 空・パスワード空 → E01（インライン）。ID `dr00002`（小文字・前後空白）→ 大文字・trim で通る。
- ID 正・パスワード違い／ID なし → どちらも E520（ID の有無を出さない）。停止（DR00005）・無効（DR00018）→ E431。
- 20 回連続で誤入力 → ロックされない（台帳 F）。ただし #1 の総当たり対策の可否を確認。
- 再設定①: 存在しない ID → E433、メール未登録 → E434。② コード `0000` → E521、5分経過 → E522、再送を連打 → S400・旧コードは無効か（要確認）。
- ③ 新パスワード 7文字・英字のみ・全角・65文字 → E523、確認用が違う → E524、8文字ぴったり・64文字ぴったり → 通る。
- 未送信が端末にある状態でログイン画面を開く → W312。ログアウト → Q317（n件）、別 ID でログイン → 未送信の扱い（#7）。
- ログイン後24時間経過で操作 → ログイン画面へ・E525・未送信は残る。作業中（入力途中）に切れたときの入力の扱い。

### DA_HOME（ホーム・配送一覧）
- 今日の担当0件 → I313。検索で0件 → I01。期間 開始＞終了 → E08、91日前 → E446、90日前ちょうど → 通る。
- 納品日が先の配送のカードをタップ → I311・詳細は開かない。受取済・トラブルあり・未送信のバッジの組み合わせ（赤・黄・青）。
- 未配送タブ × 過去日の期間（昨日の未完了は「未配送」か）→ 定義を確認（#要確認）。配送完了タブ → 完了後7日以内のみ修正導線。
- 件数11件で10件ずつのページ送り・10/20/50 切替。タブ切替で検索文字がクリアされる。
- 機内モード → 帯「オフライン・未送信」。電波復帰 → 「オンライン・未送信 N件」→「再送する」→ S403、失敗 → E445（理由別は #3）。
- 運営が配送を別ドライバーへ付け替え → 画面を開いたまま／オフラインのまま操作したときの結果。

### DA_ESDL（ES配送便）
- 荷物未受取 → 「完了」不可・I310。納品日が先で「陳列を開始」→ Q313・理由空で不可・500文字ぴったり・501文字。
- ① 写真0枚 → 続ける不可、20枚ぴったり・21枚目 → E441、5MB超・PDF・HEIC → 縮小される／E441。ギャラリーの古い写真を選べる点（不正対策は要確認）。
- ② 廃棄数＞理論在庫（#8）、実在庫 10,000 → E12、全行未チェックで「確認」→ 不可。「未確認のみ表示」・検索60文字。
- ③ 実際数を予定数と変える／未確認のまま確認 → モーダル・連絡済み未チェックで報告完了不可 → 自動トラブル（1件にまとまる）。完了後に数を直す → E440（#4）。
- ⑤ 集金あり・空で完了 → E01（完了前にインライン）、0円 → 通る、予定と違う額 → W310（警告・登録可）。集金なし → 「完了」のみ。
- 完了ボタン2連打・再送で二重に完了しない（冪等）。オフラインで完了 → W311・「未送信」・復帰で自動／手動再送。
- 駐車報告: レシートなし・料金なし → E442・E01（項目の下）、料金 0・999,999,999・1,000,000,000、全角数字。完了前・完了後7日以内・8日目 → E439。0円でレシート必須の矛盾（要確認）。
- 完了後修正中に運営が同じ配送を更新 → E31（上書きできる）。資料（委託のみ）: 自社 DR00001 で欄なし、資料なし → I316。

### DA_COOL（COOL便）
- 未受取 → I310。チェック0件で完了 → E444。全チェック → 確認なしで完了 S314。一部のみ → Q311・連絡済みチェック必須。
- 納品日前に完了 → Q313（理由必須・500文字）。完了後「内容を修正する」→ 7日以内可・8日目 E439・トラブルあり E440。

- オフラインで完了 → W311・再送。一部未配送で完了 → 自動トラブル（種別未定）が運営に出る。

### DA_RECV（受取）
- 全箱チェック → 確認なしで完了 S312。1箱だけ → Q310・連絡済み未チェックで不可 → 完了で「箱数不足（自動）」。
- 完了後は行を押せない。「追加の荷物を受け取る」→ I312・n回目。**翌日**に遅れて届いた箱の再受取（未定義・#4）。
- 中継先（営業所コード HU…・電話コピー）→ 箱ごとに確認。2次の受取は受取済にならず区間の時刻だけ。
- 行をスクロール中の誤タップでチェックが入らないか。「未確認のみ表示」・検索（送り状番号・全角英数）0件 → I01か専用文か。
- オフラインで受取完了 → 未送信。ES へ電話 → tel: 発信・記録。

### DA_STCK（廃棄・棚卸し）
- 全部0で登録 → E448。1点以上 → 「廃棄を登録（n点）」S317・登録後0に戻る。理由（5つ）既定「賞味期限切れ」のまま登録される点。
- 廃棄数 −で0未満にならない、9,999・10,000 → E12。バーコード: 一覧外の商品 → 行が足される、見つからない → E329、カメラ拒否 → I226。
- 納品先なし → I315。棚卸なしの拠点 → I318（表・送信なし）。納品先を切り替えると棚卸し表が変わる・入力は残るか。
- 棚卸し: 初期＝理論在庫で何も触らず送信（#9）。差異あり → S318・差異なし → S208。実在庫＞理論在庫でも送信できる。
- 入力途中で戻る・タブ移動・再読み込み → Q02（ES配送便との不統一）。オフライン → 未送信・二度押し防止。
- 法人Web が最終報告済みの月度に送信、21日以降に送信。

### DA_RPTD（トラブル報告）
- 対象未選択 → 次へ不可。受取地点: 箱数不足・誤配送・荷物破損は送り状番号0件 → E02（項目の下）。「その他」で備考空 → E01、500・501文字。
- 画像20枚・21枚・5MB超・形式NG。同じ対象・同じ種類の未解決あり → Q316 追記（件数は増えない）。オフラインで同種を2回 → 再送後に1件へまとまるか。
- 送信確認 Q315 の二度押し。送信後 S315・戻り先（元画面／ホーム）。入力後の戻る → Q02。
- 配送完了後の配送が対象に出ないこと（Q-DW09 採用時）。報告後に完了後修正が E440 になること。

### DA_MANU（マニュアル）
- URL 設定あり → ホーム・アカウントのボタン → 別タブ。URL 空 → 両方のボタンが出ない（文言も出さない）。
- 設定側 http(s) 以外・256文字 → E10。URL を変えた直後の反映（キャッシュ）。ホーム画面追加（PWA）での開き方。

### DA_NOTI（お知らせ）
- 0件 → I01。未読 → 太字・ベルの赤丸、詳細を開く → 既読・赤丸が消える（複数端末で同じか）。
- 重要 → 「【重要】」（二重に付かない）。公開開始日が明日 → 出ない。存在しない番号 → I400・ホームに戻る。
- 11件以上 → 10件ずつ（Q-DW14 採用時）。自動通知（割当・日付変更）が混ざる順序。当日の割当変更がアプリを開くまで気づけない点（プッシュなし）の確認。

## (c) 機械が指摘したが「報告不要・報告違い」の点

- **D1（検索・商品の検索 60字なのに欄が15〜19字分）**: 検索欄は画面幅いっぱいで足りる。最大文字数は上限で、全部見せる必要はない。→ 報告違い（HOME 008〜013、ESDL 013・014・018、RECV、RPTD、STCK 計 9 組）。
- **D5（必須項目・主ボタンが初期表示の外）**: 撮影が全ページを伸ばした画像（STATIC_CSS）なので、実機では下に固定のボタンが常時見える（STCK 7・COOL 11 は「下に固定」と記載）。→ 報告違い。
- **D6（任意の下に必須）**: 表の行内の並び（廃棄数→理由）で、グループの意味がある。→ 報告違い。
- **D2（理由「代替品の回収（不良品）」が4px長い）**: スマホはネイティブの選択画面で全文が出る。閉じたとき末尾が切れるだけで影響は小さい。→ 低（修正不要でよい）。
- **Q4（写真の削除に成功・失敗のメッセージがない）**: 端末内の下書き操作なので不要。ただし確認・取り消しがない点は #13 に含めた。
- **Q6（入力エラーの状態がない）**: HOME 002・RECV・COOL・STCK 004 等は検索欄のみ・チェックのみで、エラー状態は別 view（ESDL・RPTD）にある。→ 報告違い。ESDL 002・003・005・006 の「Q6」は 005・006（駐車）で既にある。
- **U3（0件の状態なし）ESDL 003・005**: 003 はモーダル、005 は入力画面。0件の概念がない。→ 報告違い。
- **U4（キャンセル／戻る）**: 戻る＝画面移動、キャンセル＝モーダルを閉じる・修正を捨てる、で使い分けている。→ 報告違い（ただし完了後修正の「キャンセル」は修正破棄の確認が必要か要確認）。
- **B4（権限なし／参照のみ状態がない）**: ドライバーの権限は1種。停止・無効は E431 で入れない。→ 報告違い。
- **B5 DA_AUTH 003〜005 の「Cognito を使うか」**: 古い（決定済み）。報告は正しいが中身は #2 のとおり。
- **U1（ボタン名が長い）**: 「追加の荷物を受け取る（同日・再受取）」はスマホで2行で足りる。→ 低。
- **D7（番号の順が画面の並びと違う）**: 本物の指摘だが低（STCK 001 は No.4 と No.5 の入れ替え程度）。表の15件には入れていない。
- **D8（高さ 19〜23px）**: 本物。スマホは 44px 基準なので #13 でより重く見た（「サンプル写真を追加」は DEMO 専用なので対象外）。
