# 法人・拠点・子契約のCSVテンプレート（運営A）

`corps.csv`（30列）と `branches.csv`（42列）は、**設計書の列の定義**から作ったひな形です（1行目＝見出し、2行目＝記入例1行）。
元：`データ/AW_CORP_法人一覧.py`・`データ/AW_BRCH_拠点一覧.py` の状態 030 の項目 2.x、台帳 F「運営A」（更新だけ・キー＝法人ID／拠点ID・担当者は同じファイルで1行＝1人）。
形式は他のひな形と同じ（UTF-8 BOM付き・CRLF・全項目を `"` で囲む）。記入例は seed の CU00001（株式会社サンプル）／CU00643（株式会社サンプル 本社）。
コードにない列（担当者・設置フロア・ご注文のリマインドなど）の記入例は設計書の「データ例」。見出しに【】の注記は付けない（取込側は【】を外して見出しを比べるので、そのまま取り込める）。
子契約（`contracts.csv`・36列）はコードの CSV出力（`lib/csv/data.ts` の `contractsEntity`）の見出しをそのまま使い、2行目は seed の CP0000001-202703（出力の1行目）。設計書の子契約の列の定義は未作成（子契約の設計と同時・台帳 F「運営A」(6)）のため、列の並びはコードのまま。

## 列の並び
- 法人：法人ID（キー）→ 基本情報・住所・請求（2.2〜2.23）→ 担当者5列（区分・担当者名・フリガナ・メールアドレス・電話番号（担当者））→ 参照の列（配下の拠点・登録日時。変更不可＝E115）。
- 拠点：拠点ID（キー）→ 参照の列6つ（所属法人ID・所属法人名・旧ES ユーザーID・親契約番号・ログインID・登録日時。変更不可＝E115）→ 基本情報・住所・契約・請求（2.3〜2.32）→ 担当者5列。
  所属法人と契約種別は編集の列ではない（所属法人は参照のみ。契約種別は列に出さない）。
- 担当者は1行＝1人。同じ ID の行を並べ、2行目以降の法人・拠点の列は空欄でよい。「区分＋メールアドレス」で突き合わせ（あれば更新・なければ追加・CSVでは削除しない）。
- 記入例の空欄＝今の値のまま。支払方法など条件で無効な列は空欄にしてある（値を入れると E109）。

## コード（`lib/csv/data.ts`、`formCols` ＋ 追加列）との違い ＝ 宿題（dev）
法人（corps）
- 設計にあってコードにない列：**ご注文のリマインド**、**担当者の5列**（`formCols` は表を持つ項目を出していない）。
- 見出しの名前の違い：郵便番号・都道府県・市区町村・町名・番地・建物等・電話番号・FAX番号（コードは「…（請求書に載る住所）」）／起算月（コードは「起算月（年払いのとき）」）。
- コードにあって設計にない列：法人ステータス（参照のみ・設計の CSV 列にない）・ログインID（法人ID）・アカウントのステータス・最終ログイン日時。
- 列の並び：設計は 担当者の列が 配下の拠点・登録日時 の前。
- 法人ID の見出し：コードは「法人ID【更新だけ（新規は申込から）】」（設計は「法人ID」）。

拠点（branches）
- 設計にあってコードにない列：**設置フロア**、**担当者の5列**。
- 見出しの名前の違い：棚卸報告（コードは「在庫点検」・台帳 F どおり直す）／親契約番号（コードは「親契約番号（契約ID）」）。
- コードにあって設計にない列：所属法人（`formCols` が出す重複の列。設計は 所属法人ID・所属法人名 だけ）・契約種別・契約開始日・回収未完了（アラート）・貸出中 合計・未返却 合計・最終ログイン日時・申込時の添付資料。
- 列の並び：設計は 参照の列6つ（所属法人ID・所属法人名・旧ES ユーザーID・親契約番号・ログインID・登録日時）を 拠点ID のすぐ後ろに置く。コードは 登録日時 が最後、親契約番号・ログインID などは途中。
- 値の形：当初契約開始年月・開始サイクル月は yyyy-mm（コードの出力は「2026-02-23」「2026年3月（A1 …）」の表示用）。
- 拠点ID の見出し：コードは「拠点ID【更新だけ（新規は申込から）】」。

子契約（contracts）
- 取込は更新だけ・キー＝**子契約ID**（先頭の列）。子契約IDが空欄・見つからない行は行エラー（E101・E100）。変更は、その月から後ろの**未確定**の子契約にも当てる（確定・請求済の月はエラー）。
- 以前のコード：キーは「親契約番号＋適用開始」の2列だった → 子契約IDに変更。親契約番号・適用開始・拠点ID・拠点名・法人名・請求の状態・当月請求額は参照の列（変更不可＝E115）。
- 列は今のコードの列をそのまま（見出しの注記【】なし）。設計の列の定義が決まったら、この表と並びを直す。
- エラーの行は取り込まず、ほかの行を登録。5,000行まで。ファイル全体のエラーは E106・E107・E113・E51（法人・拠点と同じ文言）。
- 取込の画面：`/ops/contracts/import`（子契約CSV取込）。子契約一覧の「CSV取込」は画面へ進む（ボタンは『CSV出力』『CSV取込』の順）。

新規申込（契約申請管理）
- 新規申込CSV取込は画面：`/ops/applications/import`（新規申込CSV取込）。契約申請管理（新規契約タブ）の「CSV取込」は画面へ進む。列・1行＝1拠点・同じ法人キーの行＝1申込・取り込むと受付中は従来どおり（`lib/csv/apply.ts`）。ひな形は画面の「テンプレート（CSV）」から（見出しに【】の注記つき）。
- `newApplications.csv`（57列）：`lib/csv/apply.ts` の列（1行目＝見出し、2・3行目＝記入例の2拠点・同じ法人キー `A`＝1申込）。形は他のひな形と同じ（UTF-8 BOM付き・CRLF・全項目を `"` で囲む）。見出しの【】の注記は付けない（取込側は【】を外して比べる）。記入例は画面のテンプレートと同じ行で、**取込の画面（`/ops/applications/import`）にそのまま取り込めること**を確かめた（エラー0・新規1申込・受付中）。記入例の法人名・拠点名は「（例）…」なので、取り込む前に書き換える。列の説明（必須・選択肢・入力の条件）は画面のテンプレートの【】と、設計書 `データ/AW_APPL_契約申請管理.py` の状態 061〜065・067（CSV取込）を見る。
- エラーを含む法人キーの申込ごと取り込まず、ほかの法人キーの申込を登録。ファイル全体のエラーは E106・E107・E51 と同じ文言。見出しの違い（E113 相当）は「1行目の見出しが取込用の列と違います。テンプレートのファイルを元に作り直してください。」（E113 の「CSV出力のファイルを元に」は新規申込にCSV出力がないため言い換え）。

共通：取込の画面（/ops/corps/import・/ops/branches/import）・E100・E101・E102・E109・E115・E116 は台帳 F のとおりコードの宿題（モーダルのまま）。
