- お知らせ 0 件／11 件（重要 2・通常 9）→ 0 件は I01、11 件は重要が上で 10 件＋ページ送り、10・20・50 の切替で先頭ページに戻る。
- お知らせを開く（1 件だけ開く）→ 別の行を開くと前の行が閉じる。添付 10 件・1 件 5MB・HEIC は表示変換。
- 他社宛のお知らせ ID（`/supplier/notices/{id}`）／存在しない ID → I400「…見つかりません。」（存在を明かさない）、一覧に戻る導線あり。

- 1 日経過後に操作（401）→ E525 のログイン小窓、入力は消えない（棚卸のコード宿題の受け入れ条件）。

### SW_ORDR（受注一覧・発注詳細・CSV取込）
- 出荷予定日を「最初の入荷希望日」の前日／当日／翌日（個別・一括・CSV）→ 前日・当日は OK、翌日は E470（#2 確定後の期待値）。
- 一括承認で出荷予定日を過去日にした行がある → E467 が行ごと、1 件でも誤りがあれば 1 件も承認されない（all-or-nothing）。
- 本発注の一括承認で箱数＞数量・箱数×入り数≠数量 → E473／W322（#1 で足す前提）。
- 納期回答の一括承認の最中に別画面で運営が状態を変えた → E475。二重クリック → ボタンは無効化され二重に登録されない。
- 分納 1 回／3 回（上限）／4 回目→ 4 回目は「分納は n回までです」（E471）、回ごとの数量の合計≠発注数量 → E472、運営設定で上限を変えると画面も変わる。
- 出荷待ちの一覧で 1 行だけ送り状番号が `abc` → 「出荷済みにする」で全件が報告されず、誤りの行に E474。21 文字・全角数字・ハイフン混じり → 全角は半角、ハイフンは除去、21 文字以上は E474。
- 賞味期限（消費期限）＝出荷日と同じ／出荷日の翌日／希望消費期限より前 → 同日は E469、翌日は OK、希望より前は Q320（通常商品の扱いは #7 の決定後）。
- 資材の仕入先（SP00009）→ 期限の欄が出ない・必須にならない・CSV でも不要、進みの段階（#4 の決定後）。
- CSV取込：UTF-8 以外（Shift_JIS）／5,001 行／発注番号の重複行（E476）／他社・存在しない番号（E477）／分納の発注（E479）／本発注の承認で「納品日」だけ（E480）→ エラーの行は取り込まず、ほかの行は「登録」で Q10 → S10。エラー一覧 CSV が出る。
- 検索：出荷年月＝選んだ月でタブ「納期回答待ち」を見る → #8 の決定どおり（行が消えない）。詳細から戻ったとき、条件・タブ・ページ・表示件数が戻る。
- 他社の発注番号の URL 直打ち → 「発注が見つかりません。」（他社の存在を明かさない）。
- 「受注できない」→ Q01 → S325 → 取り消せない。本発注の却下 → Q01 を通ってから却下。
- 0 件の検索（`zzz`）→ I01、クリアで戻る。サーバー失敗 → E346 と再読み込み。

### SW_PROF（プロフィール）
- 「編集する」で白い欄（郵便番号・電話・住所・担当者・出荷元住所）だけ入力でき、会社名・仕入先ID・曜日・配送方法・運送会社・許可・認証は灰色のまま。送信データで編集不可の項目を書き換え → サーバーが受け付けない。
- 郵便番号＝空／6 桁／8 桁／`1030027`／`103-0027` → E01／E05／E05／保存は `103-0027`。
- 電話番号＝`03-1234-567`（10 桁未満）／全角／ハイフンなしの 10・11 桁 → E06／OK。
- 担当者メール＝`abc`／61 文字／重複（メインとサブが同じ）→ E07／61 文字目は入力欄の上限か E04 かが data に未記載（要確認）／重複は止めない・変更は運営へ通知。
- サブ担当者を追加して空のまま保存 → 各欄に E01。メイン担当者に削除ボタンが出ない。サブを削除してキャンセル → 元に戻る。
- 変更したあとキャンセル／サイドメニュー／ブラウザを閉じる → Q02。変更なしなら何も出ない。
- 2 つのブラウザで同時に保存 → あとから保存した方に E31、先に編集していた方に I02。
- 保存成功 → S01、運営へ「変更の通知」が出る。メール変更時に認証コードの宛先が新しいメールへ変わる。
- 商品マスタ 0 件 → I01。

### SW_MANU（操作マニュアル）
- 運営設定に `https://…` を登録 → 「マニュアルを開く」で新しいタブ（`rel=noopener`）、画面に入力欄なし。
- URL が空 → リンクなし・I01・メニューの「操作マニュアル」は残る。
- URL が `javascript:`／`http` 以外 → 運営Web の設定画面で保存できない（仕入先側では出さない）。
- リンク先が開けない → E482（トースト）。
- 読み込みの通信失敗 → E346 と「再読み込み」（I01 とは別）。再読み込みで直る。

### SW_AUTH（ログイン・パスワード再設定・申込）
- ログイン：空 → E01 が 2 項目、存在しない ID／申込中・却下・未発行・削除済みの ID／誤パスワード → どれも同じ E520（文言も表示の速さも同じ）、ログイン ID は残りパスワードは空に戻さない。
- ログイン ID の全角 `ＳＰ００００１`・前後の空白 → 半角に直して通る。
- 初期パスワード（8 文字以上・英数字）でログイン → ホーム。パスワード 7 文字／65 文字／英字のみ → 再設定の③ で E523。
- 再設定：ID と登録メールの組み合わせ違い → E526（どちらが違うかを言わない）、サブ担当者のメールでも通る（#3 の確認事項）、認証コード 4 桁以外 → E01／E521、5 分 0 秒／5 分 1 秒 → E522、5 回以上間違えた後に正しいコード → 現行の決定では通る（#3 の決定後に更新）。
- 新パスワードと確認が違う → E524、完了後は担当者全員へ通知メール（No.4）。
- 申込：必須の空欄（E01）・フリガナがひらがな（E03）・郵便番号 6 桁（E05）・電話 `abc`（E06）・同意なし（E527）・区分・商品を 1 つも選ばない（E02）、各 60 文字の 61 文字目、絵文字（E04/E13）。
- 申込：確認画面で「修正する」→ 入力が残る。「この内容で申し込む」を連打 → 申込が 1 件だけ、受付番号 `SA-YYYYMMDD-NNNN`、メール S9。
- 申込の途中で「ログインに戻る」／ブラウザを閉じる → Q02。同じメール・同じ会社の再申込 → 画面では止まらず運営が確認（E09 は使わない）。
- 同意の文書の URL（環境変数）が空 → リンクが出ない。入っている → 新しいタブで開く。

**hong への質問（推奨つき）**

1. 出荷予定日は「最初の入荷希望日の当日まで」で良いですか？ **推奨：まで（当日を含む）**。理由：E470・No.32.7・No.50.10 がすでに「まで」で、26.5・29 だけ直せば足りる。
2. 一括承認と CSV の本発注承認にも、個別と同じ確認を入れてよいですか？ **推奨：入れる**。理由：入れないと、一括・CSV が個別承認の規則の抜け道になる。
3. 10/08 に「5回間違えてもコードを無効にしない」と決めています。「n 回（例：5 回）間違えたらそのコードを無効にし、再送で出し直す（アカウントはロックしない）」に変えますか？ **推奨：変える**。理由：4 桁（1 万通り）・ID が推測しやすい・サブ担当者のメールでも再設定できる、の 3 つが揃うと総当たりに弱い。ロックはかけないので台帳 F「ロックなし」とは両立する。あわせて、開発に「Cognito 本番で 4 桁が実現できるか」を確認してください（私の認識では標準は 6 桁固定・要確認）。
4. 資材の発注（仮発注なし）の仕入先画面：進みは「本発注済→出荷済→入荷済」の 3 段階、タブ「納期回答待ち」は資材には出さない、納入先は「ES事務所」と表示、でよいですか？ **推奨：左記のとおり**。理由：spec 55 §9 の「仮発注なし・本発注だけ」に画面を合わせる。
5. 申込の担当者メールの確認：運営の「申込の確認」で、承認前に宛先メールを確かめる手順を足し、公開フォームの悪用対策（CAPTCHA 等）は要否を決める、でよいですか？ **推奨：承認前の宛先確認は入れる、CAPTCHA は開発確認後**。
6. 仕入先の画面に「ESキッチンが代理入力」と出しますか？ **推奨：出す**（回答内容・履歴に入力者の列）。
7. 通常商品の希望賞味期限より前の賞味期限を入れたとき、Q320（確認）を出しますか？ **推奨：出す（{期限名}で文言を切り替える）**。理由：台帳 I で通常商品にも希望期限がある。
8. 「出荷年月」を「対象年月（メニューの月）」に変えますか？ **推奨：変える**。理由：未回答の発注にも対象年月はある。
9. 「商品・月でまとめる」のページ送りは「グループを分けない（1 ページ＝10 グループ）」でよいですか？ **推奨：左記**（まとめ行の選択がページをまたがない）。
10. 配送方法＝「直送（運送会社利用）」のとき運送会社を必須にし、「自社配送」「倉庫へ持込」では非活性にしますか？ 出荷日は未来日を警告にしますか？ **推奨：左記**。
11. 出荷元の住所（PROF No.7.1）は、編集可のまま郵便番号の欄＋住所検索を足しますか、それとも見るだけにしますか？ **推奨：見るだけ（取引・出荷の条件として扱う）**。理由：台帳 F の「変更できるのは連絡先だけ」と整合し、住所検索の例外もなくなる。
12. ホームのお知らせ（確認メモ Q9）：「重要を上、次に新しい順・1 ページ 10 件・お知らせ一覧の画面は作らない」で確定してよいですか？ **推奨：確定**。理由：台帳 F は一覧の初期の並びを運営側にしか定めておらず、仕入先ホームは決まっていない。
