## 1. AW_CYCL 配送サイクル設定（/ops/delivery/schedule/cycle）— 7問
**C1. 変更履歴の列に「操作」「理由」を入れるか**
- 背景：確認メモ Q10＝A で「変更履歴を出す」と決まった。列は「日時・操作した人・項目・変更前・変更後・影響件数」。ほかの画面の変更履歴（P-HIST）の標準は「操作」「理由」も持つ。
- 食い違い：この画面の保存には「理由」の入力欄がない。
- 推奨：「操作」（作成／変更／削除）は入れる。「理由」は入れない。

**C2. 影響件数は1つの数か、内訳か**
- 背景：保存すると、予定は作り直し・出荷待ち以降は動かさず要確認へ（台帳 F 2026-10-07 Q3＝A）。保存の確認の小窓の表は内訳（作り直す／要確認／出荷指示済み）で出す。
- 推奨：履歴も内訳（作り直し n件／要確認 m件）。小窓の表と同じ分け方。

**C3. 「設定のない月（穴）」の状態 003：見本データを足すか**
- 背景：「穴」の月があると警告 I132 が出る。いまの見本データ（2026-09〜2027-04）に穴の月がなく、画面からも作れないので、この状態の画像に警告が写らない。
- 選択：見本データを足す／この状態の画像を省く。台帳 F（法人Web 版1.1 レビュー2回目）は「見本データで出せない状態は見本を作って出す」。
- 推奨：見本データを足す。

**C4. 休止の「調整」の入れ方（E168 の ID を含む）**
- 背景：休止は7日の倍数にする。足りない日は「あと n日」と出すだけで自動では足さない（Q2＝A）。仕様は休止に区分「調整」と埋め合わせ元の ID があるとだけ書き、入れ方を決めていない。E168（7の倍数にしてください）は私が仮に割り当てた ID。
- 推奨：E168 のままでよい。「あと n日」の横に「調整を追加」ボタンを置き、区分＝調整（固定）・埋め合わせ元＝その休止・日数＝不足分を初期値にする。置き場所は運営が変えられる。

**C5. 「この設定を3倉庫へ反映」に確認の小窓を出すか**
- 背景：押すと3倉庫の出荷不可枠が一度に上書きされる。仕様に確認の記述はない。
- 推奨：出す。

**C6. 保存確認の影響表の2行を残すか**
- 背景：コードの表は決定の3分け（作り直す／要確認／出荷指示済み）のほかに「お届け日の変更申請（申請中）がある配送」「知らせる委託配送先（社数）」を出している。
- 推奨：残す（参考の行として）。保存前に運営が影響を知るのに役立つ。

**C7. 保存できない役割（R）のときの見せ方**
- 背景：経理など R の役割では、コードは「設定を保存」「祝日を再取得」だけ隠し、A1 の欄や追加フォーム・削除ボタンは出したまま。権限表に書かれていない。
- 推奨：無効にして、理由を近くに出す（I03「参照のみ：{理由}」）。配送_08 §15-11「操作できないボタンは理由を近くに常時表示」。

## 2. AW_DLVR 出荷・配送管理（/ops/delivery/list ほか）— 10問
**D1. 一覧の「配送方法」を「便種別」にそろえるか**
- 背景：一覧の条件と列は「配送方法」。詳細・スケジュールは「便種別」。台帳 F でスケジュールは「便種別」に統一済み。
- 推奨：そろえる（便種別）。

**D2. 検索後のトースト「検索しました（出荷日で絞り込み・n件）」を残すか**
- 背景：コードは検索のたびに出す。共通パターン P-LIST にはない。
- 推奨：なくす。

**D3. 実績（完了日時・納品数・備考）と駐車料金を運営が直す入口**
- 背景：決定では運営が直せる（理由必須・変更履歴。配送_04 §8-4）。コードは読み取りだけ。
- 選択：編集画面に足す／実績タブの中で直す。
- 推奨：実績タブの中。実績は納品後のデータで、編集画面は予定の項目のため。

**D4. 存在しない配送No のとき**
- 背景：画面ごとの文言。ほかの運営画面は共通の「見つかりません」（E100）。
- 推奨：E100 を使う。

**D5. 日付の形式エラーの共通メッセージがない**
- 背景：コードは「yyyy-mm-dd で入力してください」を出す。日付の共通部品はカレンダー選択。
- 推奨：不要（形式エラーが出ない）。

**D6. 編集画面の日付の候補・エラー文言**
- 背景：日付を動かす規則は1つ（配送_08 §15-9）。AW_SCHD の移動の定義（E160〜E164・W130〜W132）が正。
- 推奨：同じ規則とメッセージを参照するだけ。決めることはない（確認のみ）。

**D7. 本発注より前の配送（予定）も編集から日付を変えられるか**
- 背景：台帳 L は「本発注の前は何便でも（スケジュールで）・後は1便だけ」。編集の入口は1便だけ。
- 推奨：変えられる（同じ規則・1便ずつ）。

**D8. 編集中に「メモを追加」「送り状番号の追加」「資料を追加」など即保存の操作を押せるか**
- 背景：P-MODAL-SAVE は、未保存の編集内容があるあいだは非活性にする決まり。
- 推奨：非活性にする。

**D9. 納品済・中止・取消の /edit を直接開いたとき**
- 選択：A 詳細へ戻す（I03「{理由}（見るだけ）」）／B 開くが項目を非活性／C 保存時だけ E169。
- 推奨：A。直接 URL でも編集できると思わせない。

**D10. 詳細に補助機能（項目の検索・すべて開く／閉じる・カード目次・「編集できる項目だけ」）を出すか**
- 背景：P-DETAIL-AUX はカード構成の詳細向け。この画面はタブ構成。
- 推奨：出さない。

## 3. AW_SCHD スケジュール（/ops/delivery/schedule）— 8問
**S1. CSV（月・週・日）：予定の行（配送データがまだない行）の列**
- 背景：確認メモ Q9＝B で「1行＝1配送データ（予定）」。予定には配送No・状態・ドライバーがない。
- 推奨：配送No＝空／状態＝「予定」／ドライバー＝空。サイクル・枠＝画面のセルと同じ表記。

**S2. 配送回数の選択肢**
- 背景：コード 1回〜4回、仕様（配送_08 §15-5）月1回／月2回／月4回。**台帳 B は「配送回数（1サイクル）1〜8回」**でどちらでもない。
- 推奨：**1回〜8回**。

**S3. 配送スタッフの入力**
- 背景：仕様は「部分一致の文字入力（空白は無視）」、コードは3人から選ぶ選択。
- 推奨：部分一致の文字入力。スタッフが増えるため。

**S4. 出荷件数のしきい値 300件の置き場所**
- 背景：O4 で「仮に全倉庫300件・運営が直せる値」と決まったが、どこに持つかが未決。配送_01 は「倉庫ごと」。
- 推奨：倉庫マスタの項目「出荷件数のしきい値」（既定300）。倉庫マスタの編集で直す。中部倉庫・ES事務所も300。

**S5. 移動の「理由」の入力**
- 背景：入力の共通基準は1行60字・メモ500字。コードは制限なしの1行。
- 推奨：メモ（500字・複数行）。移動の理由は説明文になる。

**S6. 「法人に通知する」（初期ON）を残すか**
- 背景：コードだけにある。移動すると委託配送先には必ず通知し、このチェックがONなら法人にも通知する。台帳 L は「お客様に確認済みですか？」と運営が確かめる運用で、自動通知の決定はない。
- 選択：残す（初期ON）／常に通知／通知しない。
- 推奨：残す（初期ON）。ただし**お客様に影響するので hong が決める**。

**S7. 一括承認の確認の見せ方**
- 背景：コードは確認の問いを案内の枠の文章で出す。共通の確認 Q11（タイトル＋結果）がある。
- 推奨：Q11 にそろえる。

**S8. 一括承認の完了のモーダル**
- 背景：コードは完了のモーダル＋トースト。共通の決まりは成功＝トースト。
- 推奨：S11 のトーストだけにする。

## 4. AW_SHIP 出荷指示（/ops/delivery/list/ship-orders）— 6問
前提：確認メモ Q4＝B。いまは手動（変更した行のCSVを出し、運営が THOMAS に登録して「送信済にする」を押す）。ES の自動送信はフェーズ3。

**H1. 倉庫の選択肢の出どころ**
- 背景：コードは「関東倉庫 WH00001」「関西倉庫 WH00002」の固定。
- 推奨：倉庫マスタの THOMAS 連携ありの倉庫から出す。

**H2. 送信履歴の表の並び・ページ送り・絞り込み**
- 背景：コードは全行を並べる（再送待ちは出荷日の近い順に上、送信済みは新しい順）。
- 推奨：並びはそのまま。20件ずつのページ送り。絞り込みは倉庫と状態。

**H3. 「変更した行のCSV」の出し方**
- 選択：再送待ちの行ごとの「CSV」ボタン／再送待ちをまとめて出すボタン。
- 推奨：まとめて1ファイル。THOMAS に1回で登録できる。

**H4. 「送信済にする」の確認と初回の多数行**
- 背景：一度 locked にすると戻せない。初回の送信は2週間分で行が多い。
- 推奨：確認を出す。初回は行にチェックして「選択した n件を送信済にする」でまとめて押せる。

**H5. 取込履歴の保持期間とページ送り**
- 推奨：24か月・20件ずつ（変更履歴の仮と同じ）。

**H6. 取込でファイル全体が不正のとき**
- 背景：列が違う・文字コードが違う・行数の上限。E51 は「CSVとして読めない」ときだけ当てられる。THOMAS の列・文字コード・行数上限は未確認（ベンダー待ち）。
- 推奨：ファイル全体を受け付けず、何も取り込まない。理由つきのエラー（新しいメッセージが1つ要る）。上限と文字コードは THOMAS に確認（open）。

## 6. AW_DINQ 委託配送先・中継先の検索（/ops/delivery/inquiries）— 4問
前提：Q-IQ2＝B で料金表・地域加算は都道府県単位。

**I1. 住所タブ：都道府県は必須か。市区町村・郵便番号は何に効くか。条件が空のとき**
- 背景：仕様（配送_01 §3-3）は「住所（都道府県・市区町村・郵便番号）・温度帯で検索」とだけ書く。対応エリアは都道府県単位なので、市区町村と郵便番号は委託配送会社の絞り込みには効かない。
- 推奨：都道府県は必須。市区町村・郵便番号は「近くの中継先」にだけ効く。空のときは案内文。

**I2. 温度帯の初期値**
- 背景：コードの初期値は「冷蔵・常温」。決定は「住所タブの初期値は空」だが、温度帯が住所に含まれるか不明。
- 推奨：空（指定なし）。

**I3. 「近くの中継先」の列と件数**
- 背景：仕様は「同じ条件で出す」とだけ書き、列を決めていない。中継先は約300件。
- 推奨：中継先ID・名称・営業所コード・住所・状態。20件ずつのページ送り。

**I4. 中継先タブ：未選択でキーワードも空のときの表示**
- 背景：決定は「初期は未選択」まで。
- 推奨：案内文を出し、全拠点は出さない。
